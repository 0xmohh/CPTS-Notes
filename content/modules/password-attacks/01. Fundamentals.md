Before you dump anything, know what you're looking at. Every credential attack reduces to one of four questions: *where does the password live, what form is it in, who can read it, and what can I do with what I steal.*

## Where Credentials Live

| Location | What's there | Access needed |
|---|---|---|
| LSASS process memory | NT hashes, Kerberos tickets, cleartext (WDigest), DPAPI keys | SYSTEM / SeDebugPrivilege |
| SAM hive | Local account NT hashes | Local Admin |
| SYSTEM hive | Boot key to decrypt SAM / LSA secrets | Local Admin |
| SECURITY hive | DCC2 cached domain creds, LSA secrets, service account passwords | Local Admin |
| NTDS.dit | Every domain account hash | Domain Admin / DC Admin |
| `/etc/shadow` | Linux account hashes | root |
| DPAPI vaults | Browser passwords, RDP creds, Outlook | Victim's active session or masterkey |
| Credential Manager | Saved domain/web/network creds | Victim user session |
| Config files | DB connection strings, API keys, service account passwords | File read |
| `history` / `.bash_history` | Passwords typed on command line | File read |
| Group Policy Preferences | `cpassword` (reversibly encrypted!) in SYSVOL | Any domain user |
| Memory of running services | Service account passwords, session keys | Process read |

## Hash Formats You'll See

**Windows (NTLM/LM)**
```
aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0
                 ^LM (empty)                ^NT hash
```
- `aad3b435b51404eeaad3b435b51404ee` = LM for empty password (LM disabled on modern Windows)
- NT hash alone is enough for Pass-the-Hash and cracking (hashcat mode `1000`)

**Kerberos**
- TGS-REP (Kerberoasting): `$krb5tgs$23$*user$DOMAIN$SPN*$...` — mode `13100`
- AS-REP (no pre-auth): `$krb5asrep$23$user@DOMAIN:...` — mode `18200`

**Linux shadow**
- `$6$salt$hash` — sha512crypt, mode `1800`
- `$y$j9T$salt$hash` — yescrypt (modern), mode `29700`
- `$5$salt$hash` — sha256crypt, mode `7400`

**Cached domain (DCC2)**
- `$DCC2$10240#user#hash` — mode `2100`, **cannot** be used for Pass-the-Hash, must crack

**Application-specific** — covered in [[08. Cracking Hashes|Cracking Hashes]]:
- KeePass, zip/7z/rar, PDF, Office, SSH private key, bcrypt, MySQL, MSSQL, Oracle, PostgreSQL

## The Golden Methodology

1. **Enumerate before dumping.** Check your privileges (`whoami /priv`, `id`, `net localgroup administrators`) before trying LSASS. Half the techniques require Admin/SYSTEM/root.
2. **Grab cleartext first.** `history`, scripts, configs, share files, Outlook .ost. Cracking takes hours; grepping takes seconds.
3. **Default + sprayed passwords.** Before brute-forcing, try `Password1`, `Welcome1`, `<Company>2025!`, `Spring2025!`, `<Season><Year>!`. Password spraying is one password across many accounts (avoids lockout).
4. **One cred → sweep the network.** Every credential should be tested with NetExec against SMB, WinRM, SSH, MSSQL on every reachable host.
5. **Crack what you can, pass what you can't.** NT hashes, Kerberos tickets, and PKI certificates are all directly reusable.

## Where to Reuse Stolen Material

| Material | Reuse directly | Must crack first |
|---|---|---|
| NT hash | Yes — PtH over SMB/WinRM/WMI/RDP | Optional |
| Kerberos TGT/TGS (.kirbi, .ccache) | Yes — PtT, inject into session | No |
| Kerberos AES key | Yes — Pass-the-Key / Overpass-the-Hash | No |
| ADCS cert (.pfx) | Yes — PKINIT → TGT | No |
| DCC2 cached hash | No | Yes |
| Linux crypt hashes | No | Yes |
| Kerberoasting / AS-REP hashes | No | Yes |
| GPP `cpassword` | Yes — AES-256 decrypt (public key) | No |

## Password Spraying vs Brute Force

**Brute force**: many passwords against one account. Fast, loud, triggers lockout.
**Password spray**: one password across many accounts. Slower, quieter, avoids most lockout policies if you respect the observation window.

A typical AD lockout is 5 attempts per 30 min. Spray with `--continue-on-success`, wait 35+ minutes, spray the next password. `kerbrute passwordspray` is the standard tool because Kerberos pre-auth checks don't always trigger lockout counters (depends on policy).

## Legal Note

Everything in this module assumes an authorized engagement with written scope — penetration test, red team, lab, or CTF. Extracting credentials outside of that scope crosses into computer-misuse law almost everywhere.
