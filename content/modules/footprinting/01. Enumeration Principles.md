---
title: Enumeration Principles
---

Enumeration isn't about finding an exploit — it's about finding every possible path to the target. The common mistake is rushing to attack the first vulnerable service you see, missing better paths that fuller enumeration would have revealed.

## The Three Principles

1. **There's more than meets the eye** — Consider all points of view. Scan from different network positions, probe with different protocols, look at both the public-facing and internal-facing surface.
2. **Distinguish between what we see and what we don't see** — A service responding on a port is obvious; a service that was there yesterday but isn't today is subtle but equally useful intel. Timeline, pattern, and absence matter.
3. **There's always more information** — Understand the target. Every detail is a lead to the next detail.

## Six-Layer Model

Enumerate in this order — each layer builds on the previous:

| Layer | What to Enumerate | Information |
|---|---|---|
| 1. Internet Presence | Externally accessible infrastructure | Domains, subdomains, vhosts, ASN, netblocks, IPs, cloud instances |
| 2. Gateway | Perimeter security | Firewalls, DMZ, IPS/IDS, EDR, proxies, VPN, Cloudflare |
| 3. Accessible Services | Public and internal services | Service type, port, version, configuration, interface |
| 4. Processes | Running services internal state | PIDs, processed data, tasks, source and destination |
| 5. Privileges | Internal permissions | Groups, users, permissions, restrictions |
| 6. OS Setup | System internals | OS type, patch level, config files, sensitive files |

Think of each layer as a set of questions you must answer before moving to the next. Skipping a layer wastes the work you'd do in the higher ones.

## The Mindset

Three habits that separate effective enumeration from busywork:

- **Document everything** — keep a running note of hostnames, IPs, versions, users, and anomalies. A detail that seems irrelevant now may matter three steps later.
- **Verify, don't assume** — if a tool says "no services", that's not confirmation of nothing. Re-scan with different flags, different timing, different source.
- **Follow the thread** — a single discovered subdomain is a lead to more. A single username format reveals the pattern for all. Pull every thread.
