Before touching the target directly, build a picture of their internet presence from public sources. This is passive recon — you don't send any traffic to the target, so detection is zero.

## SSL/TLS Certificate Mining

Every TLS certificate lists the domains it's valid for. Public certificate transparency logs let you query every certificate issued for a domain, revealing subdomains you'd never guess otherwise.

### crt.sh

```bash
curl -s "https://crt.sh/?q=inlanefreight.com&output=json" | jq .
```

Returns every certificate issued for the domain. Extract unique subdomains:

```bash
curl -s "https://crt.sh/?q=inlanefreight.com&output=json" | \
  jq -r '.[].name_value' | \
  sed 's/\*\.//g' | \
  sort -u
```

You get subdomains like:

```
account.inlanefreight.com
blog.inlanefreight.com
mail.inlanefreight.com
...
```

Many of these aren't linked from anywhere on the public site — but they exist, and they accept connections.

### Censys / Shodan

Similar idea with more features. Censys indexes certificates and open ports; Shodan indexes services globally.

```bash
# via API or web search
censys search 'parsed.names: inlanefreight.com'
shodan search 'org:"Inlane Freight"'
```

## ASN and Netblock Discovery

A company's IP space is more than just one subnet. Autonomous System Numbers (ASNs) map an organization to all the IP ranges they own.

```bash
# find ASN from any IP owned by the target
whois -h whois.cymru.com "-v 8.8.8.8"

# find all netblocks owned by an ASN
whois -h whois.radb.net -- '-i origin AS15169' | grep -Eo "([0-9.]+){4}/[0-9]+"
```

Once you have the netblocks, scan them to find hosts not accessible via DNS but still reachable:

```bash
nmap -sn <netblock>/24
```

## Subdomain Discovery — Multiple Angles

Different tools find different subdomains. Combine them for coverage.

### Passive (no traffic to target)

```bash
# crt.sh (from above)
curl -s "https://crt.sh/?q=inlanefreight.com&output=json" | jq -r '.[].name_value' | sort -u

# subfinder
subfinder -d inlanefreight.com -silent

# amass
amass enum -passive -d inlanefreight.com

# assetfinder
assetfinder --subs-only inlanefreight.com
```

### Active (sends traffic)

```bash
# gobuster — subdomain wordlist against DNS
gobuster dns -d inlanefreight.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-110000.txt

# ffuf — subdomain fuzzing via Host header
ffuf -w wordlist.txt -u http://inlanefreight.com -H "Host: FUZZ.inlanefreight.com" -fs 0
```

Active discovery catches subdomains that:
- Never got a public certificate (no TLS)
- Are internal-facing but still DNS-resolvable
- Are name-based virtual hosts (same IP, different Host header)

## vHost Enumeration

A single IP can serve many sites based on the `Host:` header. Discovering vhosts is separate from DNS subdomain enumeration — the DNS may not be set up, but the web server might still respond:

```bash
ffuf -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt:FUZZ \
     -u http://<IP> \
     -H "Host: FUZZ.inlanefreight.com" \
     -fs <baseline_size>
```

Filter out the "default site" baseline response — what's left is a vhost.

## Cloud Infrastructure Discovery

Many companies run assets in cloud. Standard patterns to probe:

- **S3 buckets:** `inlanefreight-dev.s3.amazonaws.com`, `inlanefreight-backups.s3.amazonaws.com`
- **Azure blobs:** `inlanefreight.blob.core.windows.net`
- **GCS buckets:** `storage.googleapis.com/inlanefreight-assets`

Open or misconfigured buckets leak enormous amounts of data. Tools like `cloud_enum`, `bucket-stream`, and `s3scanner` automate the hunt.

## Web Fingerprinting

Once you have hosts, fingerprint what they're running:

```bash
whatweb http://target
whatweb -a 3 http://target             # aggressive — more requests

curl -sI http://target                 # headers reveal server, framework

# wappalyzer CLI
wappalyzer http://target
```

Look for:
- Web server (`Apache/2.4.41`, `nginx/1.18.0`, `IIS 10.0`)
- Framework (WordPress, Drupal, Django, Rails)
- Language hints (PHP, Node, .NET)
- CDN / WAF (Cloudflare, Akamai, AWS WAF)
- Versions — leads to CVE research

## Methodology

1. Start with `crt.sh` — fastest coverage
2. Supplement with `subfinder` + `amass -passive`
3. Confirm live subdomains with `httpx` or `httprobe`
4. Active DNS brute-force for anything passive missed
5. vHost fuzzing with `ffuf`
6. Build ASN/netblock map, scan with `nmap -sn`
7. Fingerprint each live host
8. Document everything — hostname, IP, tech stack, response codes
