title: ZAP Fuzzer
---

ZAP's answer to Intruder. Not as feature-rich — no attack-type dropdown with Cluster Bomb / Pitchfork / Battering Ram semantics — but the killer advantage is **no speed throttle**. On the free tier ZAP Fuzzer vastly outruns Burp Community Intruder.

## When to Use It Over Intruder

- You're on Burp Community and need more than a few hundred requests
- You want built-in wordlists without downloading SecLists
- You're already in ZAP for the engagement
- You need high-thread concurrency without a Pro license

## Starting a Fuzz

1. Capture a sample request in History (e.g. `GET /test/`)
2. Right-click in History → `Attack > Fuzz`
3. The Fuzzer window opens with the request on the left

## Fuzz Locations

ZAP's equivalent to Burp payload positions. Highlight the value you want to replace in the request, click `Add` on the right-side pane. A green marker shows where payloads will go.

Multiple fuzz locations are supported. ZAP iterates through them based on the strategy you select (depth-first or breadth-first in Options).

## Payloads

With a location selected, add payloads. Click `Add` in the payloads window, pick a type:

- **File** — load a wordlist from disk
- **File Fuzzers** — ZAP's bundled wordlists (dirbuster, jbrofuzz, SQL payloads)
- **Strings** — paste entries directly
- **Numberzz** — numeric ranges with step
- **Regex** — generate strings matching a pattern
- **Script** — run a custom script per iteration

> [!tip] Built-in wordlists save setup time
> ZAP ships with dirbuster's lists (`directory-list-1.0.txt`, `directory-list-2.3-*.txt`), JBroFuzz categories (SQL injection, XSS, path traversal, fuzzdb), and more. Add more via the ZAP Marketplace.

Example for directory fuzzing: `Type: File Fuzzers` → `dirbuster > directory-list-1.0.txt`.

## Processors

Per-payload transforms, like Burp's Payload Processing:

- Base64 Encode / Decode
- MD5 / SHA-1 / SHA-256 / SHA-512 Hash
- Postfix String / Prefix String — append/prepend static text
- URL Encode / Decode
- Script — custom per-payload logic

For directory fuzzing with special chars in the wordlist, add URL Encode so your payloads don't break the request. Click `Generate Preview` to see how each payload lands in the final request.

## Options

- **Concurrent Scanning Threads per Scan** — default 5, bump to 20+ for speed (watch server limits)
- **Retries on IO error** — default 3
- **Delay in milliseconds** — insert a pause between requests (for WAF evasion)
- **Follow Redirects** — usually off; you want to see the 3xx to know a resource exists
- **Strategy**:
  - **Depth First** — exhaust wordlist on position 1, then move to position 2 (try every password for alice, then every password for bob)
  - **Breadth First** — try each payload at all positions before moving to next payload (every user with `password1`, then every user with `password2` — classic password spray)

> [!note] Breadth First = password spraying
> If you're running an Active Directory password spray against OWA or similar, pick Breadth First with a small password list. One login attempt per user per round, pause between rounds to stay under lockout thresholds.

## Running the Fuzz

Click `Start Fuzzer`. Results populate live in a table showing:
- Task ID
- Method, URI
- HTTP code
- Reason / status text
- RTT (round-trip time)
- Size Resp. Body
- State / Custom fields
- Payload used

Sort by Code to find `200`s, by Size to find anomalies, or by RTT for time-based blind detection (SQLi sleep payloads).

Click any row to see the full request and response in the lower pane.

## Example — Directory Discovery

1. Browse to `/test/` through ZAP so you have a request in History
2. Right-click in History → `Attack > Fuzz`
3. Highlight `test` → `Add`
4. Payload: `File Fuzzers` → `dirbuster > directory-list-1.0.txt`
5. Processor: URL Encode
6. Options: Threads = 20
7. Start Fuzzer
8. Sort by Code → find `200` hits (e.g. `skills` → `/skills/` exists)

## Burp Intruder vs ZAP Fuzzer at a Glance

| Feature | Burp Intruder | ZAP Fuzzer |
|---|---|---|
| Free speed | 1 req/sec | Unthrottled |
| Attack types (Cluster Bomb, Pitchfork) | Yes | No (strategy = depth/breadth) |
| Built-in wordlists | Pro only | Yes (File Fuzzers) |
| Grep match flagging | Yes | No (filter results manually) |
| Payload processing chain | Multi-rule, ordered | Yes (Processors) |
| Resource pool / concurrency | Yes | Yes |
| Extension payload sources | BApps | ZAP Marketplace / Scripts |

Pick Intruder when you have Pro and want Grep Match + attack-type semantics. Pick ZAP Fuzzer when you need raw speed without a license.
