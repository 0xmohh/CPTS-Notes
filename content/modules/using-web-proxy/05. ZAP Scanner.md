title: ZAP Scanner
---

ZAP's scanner is open-source and free, which makes it the go-to when Burp Pro isn't an option. Feature set is close to Burp: spider (crawler), passive scanner, active scanner, reporting. It won't match Pro's research-team updates for coverage, but it's genuinely strong — especially combined with the ZAP Marketplace for extra rules.

## Spider

ZAP's crawler. Builds the site tree by following links from a starting URL.

### Starting a Spider

- From History: right-click request → `Attack > Spider`
- From HUD (pre-configured browser): `Spider Start` button on the right pane
- Standalone: `Tools > Spider` or just click the Spider icon

When you start, ZAP may prompt to add the target to scope — say Yes. Scope in ZAP controls which URLs the spider will follow (keeps it from wandering off to third-party CDNs).

### Spider vs AJAX Spider

- **Spider** — static link crawling. Fast, misses JS-rendered routes and SPAs
- **AJAX Spider** — launches a headless browser, executes JS, follows XHR / dynamic routes. Slower but catches modern app routes

> [!tip] Run both on SPAs
> For React / Vue / Angular apps, the regular Spider will find almost nothing. Run AJAX Spider second — it'll surface routes only visible after JS execution.

Results populate the Sites tab on the left pane.

## Passive Scanner

Runs automatically on every response that passes through ZAP. Zero extra requests. Fires on any traffic — proxy, spider, fuzzer, active scanner — all feed the passive scanner.

Alerts it catches:
- Missing security headers (X-Frame-Options, CSP, HSTS)
- Cookie flag issues
- Information disclosure (debug info, stack traces, comments)
- DOM XSS indicators from static source analysis
- Cross-domain misconfiguration (overly permissive CORS)

Alerts appear in two places:
- Left pane: alerts for the current page
- Right pane / Alerts tab: all alerts for the site

> [!note] Passive scan has no risk of breaking the target
> Enable it always. Even casual browsing surfaces findings.

## Active Scanner

The equivalent of Burp's Active Scanner. Actively sends payloads to every parameter, header, and cookie it can identify.

### Starting an Active Scan

- Right-click a URL in Sites → `Attack > Active Scan`
- HUD: `Active Scan` button (lightning icon) on the right pane
- From Alerts: run active against a specific finding

If you haven't run Spider yet, ZAP will automatically spider first to build a target list.

### Scan Policies

`Analyse > Scan Policy Manager` to control what checks run. Each policy has:
- **Threshold** — Off / Low / Medium / High. Lower = more aggressive (more false positives but fewer misses)
- **Strength** — Low / Medium / High / Insane. Higher = more payloads per insertion point

Pre-built policies ship with ZAP. Edit them or clone for engagement-specific tuning.

> [!tip] Lower threshold = more findings, more noise
> For a thorough one-time audit, drop thresholds to Low and set Strength to High on the checks you care about. For routine scans, Medium/Medium keeps the signal-to-noise acceptable.

### Watching the Scan

The main ZAP UI shows:
- Active Scan tab with progress bar
- Request/response pairs as they're sent
- Alert count growing as findings surface

Long scans run for hours. Don't wait on them — check back later.

## Alerts

`Alerts` tab on the left shows every finding, grouped by type and severity.

- **High** — RCE, SQLi, OS command injection, SSRF, path traversal to sensitive files
- **Medium** — XSS, CSRF, weak auth, insecure deserialization (sometimes)
- **Low** — missing headers, verbose errors
- **Informational** — notes, comments, framework fingerprints

Click an alert to see:
- Description, impact, remediation
- Request/response that triggered it
- Attack string used
- Evidence (the string ZAP matched in the response)

Right-click → `Replay in Browser` or `Replay in Console` to re-run the proof request.

> [!tip] Verify every High before celebrating
> ZAP flags `Remote OS Command Injection` with Medium confidence on findings that are sometimes false. Replay the request manually. Change the command. Confirm the behavior. Then write it up.

## Contexts and Authentication

ZAP's `Context` concept groups URLs for scanning with shared config — credentials, authentication method, session management, included/excluded URLs.

`Sites` tree → right-click site → `Include in Context > New Context`. In the context dialog:
- **Authentication** — Form-based, HTTP/NTLM, JSON, Script, Manual
- **Users** — credentials ZAP will use during scans
- **Session Management** — cookie-based, HTTP auth, script-based
- **Forced User** — pin ZAP to a specific user for all requests

Authenticated scans dramatically widen scanner coverage. Always configure a context if you have creds.

## HUD Scanning

The HUD overlays scan controls on the pre-configured browser. While browsing, you can:
- Hit `Spider` or `AJAX Spider` on the current page
- Trigger an Active Scan against the current context
- See alerts for the current page in the left margin
- Reveal hidden form fields or comments inline

Good for interactive testing where you want to spider and scan as you navigate, rather than as a separate pass.

## Reporting

`Report > Generate Report` → pick format (HTML, Markdown, XML, JSON). Customize which risk levels and alert types to include.

Templates include:
- `Traditional HTML Report` — classic, client-friendly
- `Modern HTML Report` — cleaner styling
- `Risk-based Report` — grouped by severity
- `Markdown` — good for pasting into reports

> [!warning] Same rule as Burp — don't ship the raw report
> ZAP's HTML is decent, but it's still appendix material. Your own writeup contextualizes findings against the engagement, chains vulns, and maps to business impact. The scanner tells you WHAT; you tell the client WHY IT MATTERS.

## Burp Scanner vs ZAP Scanner

| | Burp Pro Scanner | ZAP Scanner |
|---|---|---|
| Cost | Paid | Free |
| Research update cadence | Frequent, pro team | Community + Checkmarx-backed |
| Crawler | Fast, modern | Spider + AJAX Spider |
| False positive rate | Low | Moderate — verify manually |
| Custom policies | Yes | Yes (Scan Policy Manager) |
| Auth support | Record login, creds | Contexts with multiple auth methods |
| Extensions | BApp Store | ZAP Marketplace |

Use Burp if you have a license. Otherwise ZAP, with careful triage, gets you most of the way there.
