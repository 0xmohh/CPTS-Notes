title: Burp Intruder
---

Intruder is Burp's fuzzer. It takes any request and replays it with payloads inserted at marked positions. Use it for directory brute-force, parameter discovery, credential stuffing, SQLi payload lists, IDOR enumeration — anywhere you need to iterate over a request.

> [!warning] Community edition is throttled to 1 request per second
> On the free tier, keep wordlists short (hundreds, not thousands). For big lists use ZAP Fuzzer or `ffuf`. Pro has unlimited speed.

## Sending a Request to Intruder

Capture a request in Proxy History, right-click → `Send to Intruder` (or `CTRL+I`). Jump there with `CTRL+SHIFT+I`.

The `Target` tab pre-fills from the captured request — host, port, HTTPS flag.

## Payload Positions

The `Positions` tab is where you mark insertion points with `§` markers. Select the value you want to fuzz, click `Add §`.

Example — directory brute-force:
```
GET /§DIRECTORY§/ HTTP/1.1
Host: target
```

> [!tip] Keep the trailing blank lines in the request
> Deleting the two blank lines at the end of an HTTP request will cause the server to error or hang. Burp won't fix it for you.

## Attack Types

Chosen from the dropdown above the request. This is the one decision that defines how Intruder iterates.

### Sniper (default)

One payload set, one position at a time. If you mark three positions, Sniper runs the wordlist against position 1 with 2 and 3 untouched, then position 2, then position 3.

Use for: single-field fuzzing, parameter discovery, SQLi payloads on one field at a time.

### Battering Ram

One payload set, same value in **all** marked positions simultaneously. Each request puts the current payload in every spot.

Use for: scenarios where the same value should appear in multiple places (e.g., username in URL path AND body AND Referer).

### Pitchfork

N payload sets, 1:1 parallel iteration. If set 1 is `[alice, bob, carol]` and set 2 is `[pass1, pass2, pass3]`, requests are `alice+pass1`, `bob+pass2`, `carol+pass3`.

Use for: known credential pairs (dumped combo lists where user[i] goes with pass[i]).

### Cluster Bomb

N payload sets, full Cartesian product. Set 1 × Set 2 × Set 3. With 100 users × 100 passwords = 10,000 requests.

Use for: credential stuffing, username/password spraying, any brute-force where every combination must be tried.

## Payload Sets

The `Payloads` tab configures what gets injected.

### Payload Type

- **Simple list** — load a wordlist file or paste entries. Most common choice.
- **Runtime file** — streams line-by-line from disk; use for huge lists to avoid memory bloat
- **Numbers** — generates numeric sequences with step and format
- **Character substitution** — permutes characters (good for password munging)
- **Case modification** — case variants of each entry
- **Username generator** — derives usernames from full names
- **Dates** — generates date ranges in various formats

### Loading Wordlists

For simple lists, click `Load` and point at a SecLists file:
```
/opt/useful/seclists/Discovery/Web-Content/common.txt
/opt/useful/seclists/Passwords/Common-Credentials/10-million-password-list-top-1000.txt
/opt/useful/seclists/Usernames/top-usernames-shortlist.txt
```

### Payload Processing

Transforms applied to each payload before it's inserted. Click `Add` under `Payload Processing` to pick a rule:

- **Skip if matches regex** — filter wordlist (e.g. `^\..*$` to skip hidden files)
- **Prefix / Suffix** — add static text before/after each payload
- **Hash** — MD5, SHA-1, SHA-256, etc.
- **Encode / Decode** — base64, URL, HTML
- **Match/replace** — regex substitution
- **Invoke Burp extension** — custom transforms from BApps

Multiple rules apply in order. Great for turning a username list into email addresses, hashing passwords before send, etc.

### Payload Encoding

At the bottom of the Payloads tab. By default Burp URL-encodes certain characters (`./^=<>&+?*:;'{}|^`) before sending.

> [!warning] Disable URL-encoding when fuzzing extensions or raw bytes
> If you're fuzzing file extensions like `.php`, `.phtml`, Burp will URL-encode the `.` to `%2E` and your request becomes `shell%2Ephp`. Uncheck `URL-encode these characters` for extension fuzzing.

## Settings — Grep Match

Flags responses that contain specific strings. The whole point: scan 10,000 responses in seconds by looking at a `✓` column instead of eyeballing each.

1. `Settings` tab → `Grep - Match`
2. Enable it, clear defaults
3. Add strings that indicate success:

```
200 OK              # for directory discovery
Welcome back        # for login success
Invalid username    # for user enumeration (negative → invert)
SQL syntax          # for SQLi error detection
<title>Admin        # for authz testing
```

4. Uncheck `Exclude HTTP headers` if the string is in headers (status lines, cookies)

In the results window, sort by the grep column to surface hits at the top.

## Settings — Grep Extract

Pulls specific text out of each response. Useful when responses are huge and you only care about one field (a CSRF token, a user ID, a balance).

Define a start/end delimiter around the value you want; Intruder adds a column showing just that value.

## Settings — Resource Pool

Controls concurrency and delay. For Pro, bump threads up for speed. For engagements with WAF/rate-limiting, add a delay between requests to stay under thresholds.

## Running the Attack

Click `Start attack`. The results table shows:
- Payload used
- Status code
- Response length
- Time taken
- Grep columns (one per Grep Match rule)

Sort by Length or Status to spot anomalies. A `200 OK` with a different length than the rest usually means you hit something real.

> [!tip] Length is often more reliable than status
> Many apps return `200 OK` for both success and failure (SPAs especially). Sort by Length — one response size that stands out is usually the valid user, correct password, or existing directory.

## Example — Directory Brute-Force

1. Capture `GET /test/ HTTP/1.1` in Proxy History
2. `CTRL+I` to Intruder
3. Positions tab: mark `test` with `§`
4. Attack type: Sniper
5. Payloads: load `/opt/useful/seclists/Discovery/Web-Content/common.txt`
6. Payload processing: `Skip if matches regex` → `^\..*$` (skip hidden files)
7. Payload encoding: uncheck URL-encode
8. Settings → Grep Match: add `200 OK`, uncheck Exclude HTTP headers
9. Start attack
10. Sort by `200 OK` column — valid directories float to the top

## Example — Login Brute-Force with Cluster Bomb

1. Capture `POST /login` with `username=admin&password=admin`
2. Send to Intruder
3. Positions: mark both `admin` values → `§admin§` and `§admin§`
4. Attack type: Cluster Bomb
5. Payloads set 1: username wordlist
6. Payloads set 2: password wordlist
7. Grep Match: add `Invalid` (or whatever the failure string is)
8. Start — sort by Grep (NOT matching Invalid) to find successful logins
