title: WHOIS and DNS
---

WHOIS and DNS are the two oldest sources of domain intelligence. Both are passive — no traffic reaches the target — making them the natural starting point for any engagement.

## WHOIS

WHOIS queries registration data for a domain: registrar, owner contact, creation/expiration dates, nameservers.

```bash
whois example.com
```

### What to Look For

- **Registrant name / organization** — confirms ownership, sometimes reveals internal naming
- **Contact emails** — email format gives you user discovery patterns (`first.last@company.com`)
- **Registrar** — some registrars allow easier abuse / takeovers
- **Nameservers** — points to DNS providers (Cloudflare, Route53, internal)
- **Creation date** — recently-registered domains look suspicious in reports
- **Admin/Technical contact** — targets for social engineering

Many modern domains use WHOIS privacy (`REDACTED FOR PRIVACY`, `Contact Privacy Inc.`), which hides the useful fields. Still check — not every org pays for privacy.

### Historical WHOIS

Services like WhoisFreaks, SecurityTrails, DomainTools track WHOIS changes over time. Useful because:

- Older records may predate privacy services, exposing original contact info
- Pattern of ownership changes can reveal M&A activity, shell companies
- Changes in nameservers hint at infrastructure migrations

## DNS Enumeration

Covered in depth in the Footprinting module. Quick summary of what matters here:

### Record Types Worth Querying

```bash
dig A TARGET.com                 # IPv4 addresses
dig AAAA TARGET.com              # IPv6
dig MX TARGET.com                # mail servers
dig TXT TARGET.com               # SPF, DKIM, verification tokens
dig NS TARGET.com                # nameservers
dig CNAME subdomain.TARGET.com   # alias — often reveals cloud provider
dig SOA TARGET.com               # zone admin
```

### TXT Records Are Intelligence Gold

```bash
dig +short TXT TARGET.com
```

Returns things like:

```
"v=spf1 include:_spf.google.com include:mailgun.org ~all"
"google-site-verification=xxxxx"
"MS=ms12345678"
"atlassian-domain-verification=xxxxx"
"stripe-verification=yyyy"
"docusign=xxxxx"
```

Each line tells you about services the organization uses:

- `include:_spf.google.com` → Google Workspace for email
- `include:mailgun.org` → Mailgun for transactional email
- `google-site-verification` → Google Workspace admin
- `MS=` → Microsoft 365
- `atlassian-` → Jira/Confluence likely at `atlassian.target.com` or similar
- `stripe-verification` → Payments via Stripe
- `docusign=` → Uses DocuSign

Each service = potential subdomain to probe + potential attack surface (phishing with legitimate branding).

### DMARC

```bash
dig +short TXT _dmarc.TARGET.com
```

Returns:

```
"v=DMARC1; p=quarantine; rua=mailto:dmarc@TARGET.com"
```

- `p=none` — DMARC configured but not enforced; spoofing works
- `p=quarantine` — spoofed email lands in spam
- `p=reject` — spoofed email rejected
- `rua=mailto:` — DMARC aggregate reports go to this address

For phishing engagements, a `p=none` or missing DMARC is a huge enabler.

### Zone Transfer Attempt

Rare these days but always worth trying:

```bash
for ns in $(dig +short NS TARGET.com); do
  echo "=== $ns ==="
  dig axfr @$ns TARGET.com
done
```

Success = entire zone exposed = every hostname in one query.

## Combining WHOIS + DNS

These two layers inform each other:

1. WHOIS reveals the registrar + nameservers
2. DNS reveals subdomains, mail infra, cloud services
3. TXT records in DNS reveal third-party integrations
4. Each integration implies a login surface at that provider (Workday, Salesforce, Zendesk) — potential credential-stuffing targets

Build a table:

| Source | What It Told You |
|---|---|
| WHOIS | Registered by Example Inc., admin contact john@example.com |
| NS | Google DNS (likely Google Workspace) |
| MX | aspmx.l.google.com (confirmed Google Workspace) |
| TXT SPF | +Mailgun, +SendGrid |
| TXT verification | +Atlassian, +Stripe |
| Subdomains | docs.example.com, jira.example.com, status.example.com |

That's a complete first-pass intel profile without sending a single packet to the target.
