---
title: Crawling and Well-Known URIs
---

Crawling extracts content, links, and files from a web application in a structured way. The `.well-known` directory is a standardized metadata endpoint that reveals how the app integrates with external services — often more valuable than regular content.

## Crawling Strategies

### Breadth-First

Explore all links on the current level before going deeper. Good for mapping a site's overall structure quickly.

### Depth-First

Follow one path as far as possible, then backtrack. Good for finding content buried deep in navigation.

Most tools let you choose or do both. The trade-off is time vs completeness.

## Automated Crawlers

### Burp Suite Spider / Scanner

If you're already using Burp (free or Pro), its spider traverses discovered content. Pro's active scanner adds fuzzing on top.

### OWASP ZAP Spider

Equivalent for the open-source side. Has a "Forced Browse" plugin that layers wordlist-based discovery over natural crawling.

### `gospider`

Fast Go-based crawler:

```bash
gospider -s "https://TARGET.com" -d 3 -c 20 --other-source
```

- `-d 3` — crawl depth
- `-c 20` — concurrency
- `--other-source` — also pull from Wayback Machine, Common Crawl, VirusTotal

Output includes every URL, form field, API endpoint discovered.

### `katana`

Modern headless-browser crawler from ProjectDiscovery — handles JavaScript-rendered sites that static crawlers miss:

```bash
katana -u https://TARGET.com -d 5 -js-crawl -jsluice
```

- `-js-crawl` — execute JS to find dynamically-generated links
- `-jsluice` — extract secrets from JS files (API keys, endpoints)

### `hakrawler`

Focused on speed and chaining:

```bash
echo "https://TARGET.com" | hakrawler -d 3 | sort -u
```

### `waybackurls`

Not a live crawler — pulls every URL ever recorded for a domain from Wayback Machine:

```bash
echo "TARGET.com" | waybackurls | sort -u
```

Reveals:
- Historical endpoints that still exist
- Old API versions
- Deprecated paths that may still be unprotected
- Forgotten dev/test paths

## What to Extract From Crawling

- **All URLs** — endpoint inventory
- **Forms** — input vectors for XSS, SQLi, CSRF
- **JavaScript files** — API endpoints, secrets, keys
- **Comments in HTML** — developer notes, TODO items, old credentials
- **Upload endpoints** — attack targets for File Upload module
- **AJAX / fetch calls** — hidden endpoints the UI doesn't link

### JavaScript Mining

Static JS analysis finds things dynamic crawlers miss:

```bash
# extract all JS files
katana -u https://TARGET.com -no-sandbox -silent -jc | grep "\.js$" | sort -u > js-files.txt

# download them
wget -i js-files.txt

# grep for interesting strings
grep -r "api_key\|apikey\|secret\|token" .
grep -r "/api/" .
grep -oP "https?://[^\"']+" .
```

Tools like `linkfinder.py`, `secretfinder.py`, `trufflehog` automate this.

## The `.well-known/` Directory

Standardized paths at `/.well-known/*` that applications use to advertise metadata and configurations. Automatically discoverable.

### Entries Worth Checking

| Path | What It Reveals |
|---|---|
| `security.txt` | Vulnerability reporting contact, bug bounty scope |
| `openid-configuration` | OIDC endpoints — auth URL, token URL, JWK URI (potential JWT attacks) |
| `oauth-authorization-server` | OAuth 2.0 server metadata |
| `assetlinks.json` | Linked Android apps (APK package IDs, cert fingerprints) |
| `apple-app-site-association` | Linked iOS apps (bundle IDs, universal links) |
| `change-password` | Standardized password change endpoint — target for CSRF, credential brute force |
| `mta-sts.txt` | Email server policy, lists mail hostnames |
| `ai-plugin.json` | ChatGPT plugin metadata — internal APIs exposed to AI |
| `host-meta` | Host-wide metadata, service discovery |
| `webfinger` | User discovery for ActivityPub/Mastodon |

### Quick Enumeration

```bash
for path in security.txt openid-configuration oauth-authorization-server \
            assetlinks.json apple-app-site-association change-password \
            mta-sts.txt host-meta ai-plugin.json webfinger; do
  code=$(curl -s -o /dev/null -w "%{http_code}" https://TARGET.com/.well-known/$path)
  echo "$code  /.well-known/$path"
done
```

200 responses = investigate those endpoints.

### Why It Matters

- **`openid-configuration`** — reveals OAuth/OIDC endpoints. Attack vectors: JWT signing attacks, token redirects, open redirects in auth flows, scope confusion.
- **`security.txt`** — tells you if there's a bug bounty (do you have legal protection?), and provides emails that identify the security team.
- **`assetlinks.json` / `apple-app-site-association`** — reveals mobile apps you can decompile for additional recon (hardcoded API endpoints, keys).
- **`change-password`** — some apps implement this as a direct CSRF-vulnerable endpoint.
- **`mta-sts.txt`** — mail server infrastructure map, useful for phishing/spoofing.

## Robots.txt and Sitemaps

Not `.well-known` but same spirit:

```bash
curl https://TARGET.com/robots.txt
curl https://TARGET.com/sitemap.xml
```

`robots.txt` often lists paths the site *doesn't* want indexed — meaning they're interesting:

```
Disallow: /admin/
Disallow: /api/v1/internal/
Disallow: /_dev/
```

Those disallowed paths usually still exist and are accessible — the admin just wanted them out of Google.

`sitemap.xml` lists every page the admin wants indexed — useful content inventory.

## Methodology

1. `curl https://TARGET.com/.well-known/security.txt` (quick signal)
2. Enumerate standard `.well-known` paths
3. Read `robots.txt` and `sitemap.xml`
4. Full crawl with `katana` or `gospider` for live content
5. Fetch historical URLs with `waybackurls`
6. Download all JS files, grep for secrets and API endpoints
7. Consolidate — unique URLs, unique forms, unique API paths
