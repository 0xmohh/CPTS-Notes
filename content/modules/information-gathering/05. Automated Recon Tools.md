title: Automated Recon Tools
---

When you need to recon fast — bug bounty, time-limited engagement, or just to not spend hours on manual enumeration — these frameworks chain together many techniques.

## theHarvester

Classic for people-and-domain intel. Pulls from public sources: search engines, Shodan, LinkedIn, Google, Bing.

```bash
theHarvester -d TARGET.com -b all
```

Returns:
- Email addresses with the target domain
- Subdomains
- Employee names (from LinkedIn)
- IP addresses
- URLs

Great starting point for engagements that need both technical and people-level recon.

## ReconSpider

All-in-one OSINT tool. Grabs:

```bash
python3 ReconSpider.py
# then follow prompts: WHOIS, DNS, subdomain, port scan, reverse IP, etc.
```

Menu-driven — easier when you're not sure which single tool to run. Output is comprehensive but slower than specialized tools.

## FinalRecon

Similar scope. Modular — run only what you need:

```bash
python3 finalrecon.py --url https://TARGET.com --headers
python3 finalrecon.py --url https://TARGET.com --dns
python3 finalrecon.py --url https://TARGET.com --whois
python3 finalrecon.py --url https://TARGET.com --full
```

The `--full` run does everything — WHOIS, DNS, SSL, headers, crawler, directory enum.

## Amass (Advanced Mode)

Beyond the `-passive` quick run, Amass has active modes:

```bash
# intel mode — find related orgs, domains
amass intel -d TARGET.com -whois

# enum with brute force + permutations
amass enum -active -brute -d TARGET.com -w wordlist.txt

# viz — generate a graph of findings
amass viz -d3 -dir output-dir
```

The visualization helps when you want to understand infrastructure relationships, not just list them.

## reNgine

Full web platform for recon management. Deploy with Docker:

```bash
git clone https://github.com/yogeshojha/rengine
cd rengine
./install.sh
```

Then use the web UI to schedule scans, visualize data, track discoveries across engagements. Overkill for one-off recon; essential for continuous or multi-target workflows.

## OWASP ASST (Automated Software Security Toolkit)

Framework that integrates multiple scanners:

- Nuclei for template-based vuln scanning
- Subfinder, httpx, katana for discovery
- Nikto for broad web scans

```bash
# starts a reconnaissance pipeline
asst scan TARGET.com
```

## ProjectDiscovery Stack (Nuclei, Subfinder, httpx, katana)

Not one tool — a family that chains together elegantly:

```bash
# full pipeline
subfinder -d TARGET.com -silent \
  | httpx -silent \
  | nuclei -t nuclei-templates/ -silent
```

This single line:
1. Discovers subdomains
2. Filters to live hosts
3. Runs 5000+ vulnerability templates against each

Nuclei templates cover known CVEs, misconfigurations, default credentials, exposed panels, and more. Runs fast and produces clean output.

## When to Use What

| Scenario | Tool |
|---|---|
| Quick one-target recon | FinalRecon `--full` |
| Email + employee intel | theHarvester |
| Massive subdomain discovery | subfinder + amass + crt.sh merged |
| Known CVE scanning | nuclei |
| Continuous / multi-target | reNgine |
| Just one specific thing | the specialized tool (ffuf, gobuster, etc.) |

## The "Don't Automate Everything" Rule

Automated tools generate noise (hitting a WAF with 10K requests) and false positives. Rules of thumb:

- Use automation for **discovery** (what's out there)
- Use manual testing for **exploitation** (how do I abuse it)
- Never submit automated-tool findings to a bug bounty without manually verifying — "Nuclei reported X" is not a valid report

## Chaining Output

Most of these tools output JSON or line-delimited text — easy to pipe:

```bash
# all-in-one enumeration
subfinder -d TARGET.com -silent | \
  httpx -silent -status-code -title -tech-detect | \
  tee enum-results.txt

# feed interesting responses to nuclei
cat enum-results.txt | grep "200" | awk '{print $1}' | nuclei -t nuclei-templates/
```

This kind of pipeline becomes your personal recon framework. Build it up over time; every engagement teaches you what to add or drop.
