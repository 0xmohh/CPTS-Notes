---
title: Service-Specific Tips
---

Protocol quirks that will waste your time if you don't know them. Tool-agnostic — applies to Hydra, Medusa, and any scripted attack.

## SSH

```bash
hydra -L users.txt -P rockyou.txt ssh://10.10.10.10 -t 4 -f
```

- **Threads:** cap at 4. OpenSSH's `MaxStartups` default is `10:30:100` — above 10 concurrent pre-auth connections, the server starts dropping.
- **Rate control:** some targets install fail2ban or sshguard — 5 bad attempts in 10 min and your IP is banned for an hour. Use `-W 2` and watch for sudden connection resets.
- **Key auth:** if the server only accepts keys, password brute is pointless. Check banner / verbose output.
- **Version-specific:** old Dropbear / libssh variants had auth bypass CVEs (CVE-2018-10933). Check `-sV` before brute.

> [!tip] Check for default creds first
> `root:root`, `admin:admin`, `pi:raspberry`, `ubnt:ubnt` — try these manually before loading rockyou.

## FTP

```bash
hydra -L users.txt -P rockyou.txt ftp://10.10.10.10 -t 16 -f
```

- **Always test anonymous first:** `ftp 10.10.10.10` → user `anonymous`, pass anything.
- Fast and chatty — safe to use high thread counts (16+).
- vsftpd 2.3.4 has a famous backdoor (CVE-2011-2523) — try `user:)` as the username.

## RDP

```bash
hydra -l administrator -P passwords.txt rdp://10.10.10.10 -t 4
```

- **Lockouts bite hard.** Default Windows AD lockout is 5 attempts → 30 min lockout. Spray only.
- Keep threads at 2-4. RDP connections are expensive on both sides.
- `administrator` (lowercase a) is the default local admin name — always include it.
- Network Level Authentication (NLA) will reject bad creds fast; without NLA, every attempt opens a full GUI session (slow).

> [!warning] NLA disabled = DoS risk
> On old servers without NLA, each failed attempt allocates a GUI session. Brute-forcing can exhaust the session limit and kick real users off.

## SMB

```bash
hydra -L users.txt -p 'Winter2025!' smb://10.10.10.10 -t 1
# or with crackmapexec / netexec (preferred for AD)
nxc smb 10.10.10.10 -u users.txt -p 'Winter2025!' --continue-on-success
```

- **Prefer netexec/crackmapexec over Hydra for AD.** Native Kerberos awareness, lockout detection, more useful output.
- **Spray, don't brute.** Every failure increments the AD bad-password counter.
- NTLM hash auth: pass-the-hash works with `-p ':HASH'` style syntax in nxc.
- Null session check: `-u '' -p ''` — sometimes still works on old boxes.

## HTTP Basic Auth

```bash
hydra -L users.txt -P rockyou.txt 10.10.10.10 http-get /admin/
```

- Dumb and fast — no CSRF, no CAPTCHA, often no rate limit on legacy devices.
- Routers, IP cameras, printers, embedded admin panels — classic targets.
- If HTTPS, use `https-get`.
- Check the realm with a manual request first: `curl -I http://target/admin/` → `WWW-Authenticate: Basic realm="..."`.

## HTTP POST Form

```bash
hydra -l admin -P passwords.txt target http-post-form \
  "/login:user=^USER^&pass=^PASS^:F=Invalid"
```

The highest-friction protocol. Gotchas:

- **Dynamic CSRF tokens** — Hydra can't fetch a fresh token per attempt. Switch to a `requests.Session` script, or use `ffuf` with a cookie jar.
- **JSON bodies** — supply the full JSON in the post body, add `H=Content-Type\: application/json`.
- **Rate limiting / CAPTCHA** — triggered after ~5-10 attempts on most modern apps. Drop to `-t 1 -W 3`.
- **Multi-step flows** (username page → password page) — Hydra can't follow. Script it.
- **Account enumeration via error message** — `"Unknown user"` vs `"Wrong password"` lets you harvest users first, brute the valid ones second.

> [!tip] Always confirm the failure string
> Run Hydra with `-vV` against one known-bad credential. If it reports "success", your failure string is wrong. The marker must appear in EVERY failed response and NEVER in a successful one.

## Telnet

```bash
hydra -l root -P rockyou.txt telnet://10.10.10.10
```

- Old-school. Prompt variations are a pain — Hydra expects `login:` and `Password:` by default.
- Mostly IoT and legacy network gear now. Default creds (`root:root`, `admin:admin`, vendor-specific) often win before brute is needed.

## MSSQL / MySQL / PostgreSQL

```bash
hydra -l sa -P passwords.txt mssql://10.10.10.10
hydra -l root -P passwords.txt mysql://10.10.10.10
hydra -l postgres -P passwords.txt postgres://10.10.10.10
```

- `sa` (MSSQL), `root` (MySQL), `postgres` (PostgreSQL) are the default admin accounts — always include.
- MySQL sometimes binds to localhost only — if you can't connect manually, brute won't work either.
- PostgreSQL responds slowly on failed auth (anti-timing) — threads > 4 usually wasted.

## VNC

```bash
hydra -P passwords.txt vnc://10.10.10.10
```

- No username — password only.
- Classic 8-char password limit on old VNC (RFB 3.3). Crunch an 8-char list.

## General Gotchas

- **Firewalls between you and target:** half your attempts will silently drop. Verify with `nmap` before and during.
- **WAF fingerprinting:** Cloudflare, AWS WAF, Akamai will block Hydra's default User-Agent. Set a realistic UA via `H=User-Agent\: Mozilla/5.0...`.
- **Time-of-day throttles:** some SOCs trigger on off-hours auth volume. Running at 3am is louder, not quieter.
- **Honey accounts:** `admin`, `backup`, `test` on some targets are tripwires. One attempt against them = SOC alert.
