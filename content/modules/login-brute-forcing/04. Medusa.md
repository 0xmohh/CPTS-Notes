---
title: Medusa
---

Medusa is Hydra's sibling — massively parallel, modular, same-ish feature set. Where it shines is **many hosts at once**: Medusa's threading model dedicates threads per host, whereas Hydra tends to spawn threads per target sequentially. For a 500-host SSH sweep, Medusa is often faster and more stable.

## Syntax

```
medusa [target_opts] [cred_opts] -M MODULE [-m MODULE_OPT]
```

## Core Flags

```
-h host           # single host
-H hosts.txt      # host list
-u user           -U users.txt
-p pass           -P passwords.txt
-C combo.txt      # host:user:pass combo file
-M module         # ssh | ftp | http | smbnt | mssql | rdp | wrapper | ...
-m "KEY=VAL"      # module-specific option (repeatable)
-t 16             # threads per host
-T 8              # parallel hosts
-f / -F           # stop on success (host / global)
-n PORT           # non-default port
-e ns             # extra: n=null password, s=user as password
-O creds.txt      # write results
-v 6              # verbosity 0-6
```

## Examples

### SSH
```bash
medusa -h 10.10.10.10 -u admin -P rockyou.txt -M ssh
medusa -H hosts.txt -U users.txt -P rockyou.txt -M ssh -T 8 -t 4 -F
```

### FTP with Null and User=Pass Checks
```bash
medusa -h 10.10.10.10 -U users.txt -e ns -M ftp
```

`-e ns` tries each user with (1) empty password and (2) username as password — catches lazy admin accounts fast.

### HTTP Basic Auth Across Many Hosts
```bash
medusa -H web_servers.txt -U users.txt -P rockyou.txt -M http -m GET
medusa -H hosts.txt -u admin -P passwords.txt -M http -m DIR:/admin -m GET
```

### SMB (NT auth)
```bash
medusa -h 10.10.10.10 -u Administrator -P passwords.txt -M smbnt
medusa -h 10.10.10.10 -u Administrator -p "aad3b435b51404eeaad3b435b51404ee:hash" -M smbnt -m PASS:HASH
```

### MSSQL
```bash
medusa -h 10.10.10.10 -u sa -P passwords.txt -M mssql
```

### RDP
```bash
medusa -h 10.10.10.10 -u administrator -P passwords.txt -M rdp
```

## Hydra vs Medusa

| Dimension | Hydra | Medusa |
| --- | --- | --- |
| HTTP form support | Better (`http-post-form` is rich) | Basic |
| Multi-host parallelism | OK with `-M` | Strong (`-T` separate from `-t`) |
| Resume | Yes (`-R`) | No native resume |
| Protocols | ~55 | ~30 |
| Output parsing | Simple text | Simple text |
| Default creds (`-e ns`) | No equivalent | Yes |
| Project activity | Active | Stagnant (but stable) |

**Rule of thumb:**
- One host, web form → **Hydra**
- Many hosts, same protocol (SSH/FTP/SMB sweep) → **Medusa**
- Need to resume an aborted run → **Hydra**
- Need `-e ns` null/username checks in one shot → **Medusa**

## Module Options

Each module exposes options via `-m KEY=VAL`. List them with `-M MODULE -q`:

```bash
medusa -M smbnt -q
medusa -M http -q
```

Common HTTP module options: `DIR:/path`, `GET` / `POST`, `USER-AGENT:...`, `FORM:field`.

## Output and Logging

```bash
medusa -h 10.10.10.10 -U users.txt -P rockyou.txt -M ssh -O found.txt -v 6
```

`-v 6` prints every attempt — useful for debugging a wrong module option. Drop to `-v 4` for production runs.

> [!tip] Spray with Medusa
> `-U users.txt -p 'Winter2025!' -M smbnt -F` sprays one password across all users and stops at the first hit. Lower blast radius than Hydra's default outer-loop ordering.

> [!warning] No resume
> If Medusa crashes or you Ctrl+C, you start over. For long sweeps, split your host list into chunks and run sequentially so one failure doesn't void everything.
